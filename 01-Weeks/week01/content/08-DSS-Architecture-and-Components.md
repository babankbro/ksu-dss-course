# 8. สถาปัตยกรรมและองค์ประกอบทางเทคนิคของ DSS (DSS Architecture)

เพื่อที่จะสร้างระบบสนับสนุนการตัดสินใจที่มีประสิทธิภาพ นักพัฒนาระบบและผู้บริหารจำเป็นต้องเข้าใจว่า "หลังบ้าน" ของ DSS นั้นทำงานอย่างไร สถาปัตยกรรมมาตรฐานของ DSS (Standard DSS Architecture) ประกอบด้วยระบบย่อย (Subsystems) หลัก 4 ส่วนที่ทำงานสอดประสานกันอย่างใกล้ชิด

## 8.1 ระบบย่อยการจัดการข้อมูล (Data Management Subsystem)

ข้อมูลคือเชื้อเพลิงของ DSS หากไม่มีข้อมูลหรือข้อมูลไม่มีคุณภาพ ระบบก็ไม่สามารถทำงานได้ ระบบย่อยการจัดการข้อมูลทำหน้าที่รวบรวม จัดเก็บ จัดการ และดึงข้อมูลมาใช้

* **ฐานข้อมูลของ DSS (DSS Database):** ไม่ใช่ฐานข้อมูลเดียวกับระบบปฏิบัติการประจำวัน (Transactional Database หรือ TPS) เพราะหากดึงข้อมูลวิเคราะห์จาก TPS โดยตรง อาจทำให้ระบบขายหน้าร้านช้าลง ฐานข้อมูลของ DSS มักอยู่ในรูปของ **คลังข้อมูล (Data Warehouse)** หรือ **Data Mart**
* **ระบบจัดการฐานข้อมูล (Database Management System - DBMS):** ซอฟต์แวร์ที่ใช้ดูแลโครงสร้างข้อมูล เช่น SQL Server, Oracle, หรือระบบ NoSQL สำหรับข้อมูลขนาดใหญ่
* **สารบบข้อมูล (Data Directory / Data Dictionary):** เปรียบเสมือน "สารบัญ" หรือคลังคำศัพท์ที่ระบุว่า ข้อมูลแต่ละตัวหมายถึงอะไร เก็บอยู่ที่ไหน และมีหน่วยเป็นอะไร (เช่น 'รายได้' หมายถึงรวมภาษีแล้วหรือยัง) เพื่อให้ผู้ใช้ระดับบริหารเข้าใจตรงกัน
* **กระบวนการ ETL (Extract, Transform, Load):** กระบวนการดึงข้อมูลจากระบบต่างๆ ทำความสะอาด (Transform) และโหลดเข้าสู่ Data Warehouse ของ DSS

## 8.2 ระบบย่อยการจัดการแบบจำลอง (Model Management Subsystem)

ถ้าข้อมูลคือเชื้อเพลิง แบบจำลอง (Model) ก็คือ "เครื่องยนต์" ที่ทำหน้าที่แปลงข้อมูลให้กลายเป็นทางเลือกหรือคำตอบ ระบบย่อยนี้เป็นจุดที่ทำให้ DSS แตกต่างจากระบบสารสนเทศทั่วไป

* **ฐานแบบจำลอง (Model Base):** คลังที่เก็บรวบรวมตัวแบบทางสถิติ การเงิน หรือการจัดการเชิงวิทยาศาสตร์ (Management Science) ตัวอย่างของโมเดลได้แก่:
  - **Strategic Models:** แบบจำลองเชิงกลยุทธ์ ใช้สนับสนุนแผนระยะยาว (เช่น การควบรวมกิจการ)
  - **Tactical Models:** แบบจำลองเชิงยุทธวิธี (เช่น การวางแผนกำลังคน หรือจัดสรรงบประมาณประจำปี)
  - **Operational Models:** แบบจำลองระดับปฏิบัติการ (เช่น การจัดตารางรถขนส่งสินค้า)
* **ระบบจัดการฐานแบบจำลอง (Model Base Management System - MBMS):** ซอฟต์แวร์ที่ช่วยให้ผู้ใช้สามารถสร้าง (Create), ปรับปรุง (Update), และรันโมเดลต่างๆ ผสมผสานกันได้ 
* **กระบวนการรันโมเดล (Model Execution):** ทำหน้าที่รับตัวแปร (Parameters) จากผู้ใช้งาน นำไปคำนวณผ่านสมการ และส่งผลลัพธ์กลับไปยังหน้าจอ

## 8.3 ระบบย่อยส่วนต่อประสานกับผู้ใช้ (User Interface Subsystem)

ผู้บริหารมักไม่ใช่โปรแกรมเมอร์ ไม่ว่าโมเดลหลังบ้านจะเก่งแค่ไหน หากใช้งานยาก ผู้บริหารก็จะปฏิเสธการใช้ระบบนั้น (User Resistance) ส่วนต่อประสานกับผู้ใช้จึงมีความสำคัญเทียบเท่ากับระบบหลังบ้าน

* **การปฏิสัมพันธ์ (Dialog Generation):** ระบบที่ทำหน้าที่สื่อสารระหว่างผู้ใช้กับ DSS อาจมาในรูปแบบของ:
  - **Graphical User Interface (GUI):** หน้าจอแบบกดปุ่ม ลากวาง (Drag-and-drop) เมนูแบบ Drop-down
  - **Dashboards:** กระดานแสดงผลภาพรวมที่มีกราฟ, เกจ, และแผนที่
  - **Natural Language Interface (NLI):** ในยุคปัจจุบัน เริ่มมีการนำ AI มาใช้โต้ตอบด้วยเสียงหรือพิมพ์ข้อความถาม-ตอบ เช่น "แสดงยอดขายเปรียบเทียบปีนี้กับปีที่แล้วให้หน่อย"
* **คุณลักษณะที่ดีของ UI ใน DSS:**
  - ต้องรองรับการทำ What-if Analysis ได้ง่าย
  - ต้องอนุญาตให้เจาะลึกข้อมูล (Drill-down) จากภาพรวมลงไปถึงระดับรายละเอียดได้
  - ต้องตอบสนองรวดเร็ว (Low Latency)

## 8.4 ระบบย่อยการจัดการความรู้ (Knowledge-based Management Subsystem)

องค์ประกอบนี้มักพบใน DSS ชั้นสูง (Advanced DSS หรือ Knowledge-driven DSS) ทำหน้าที่เป็น "สมอง" ที่จำลองความเชี่ยวชาญของมนุษย์

* **ฐานความรู้ (Knowledge Base):** แหล่งเก็บรวบรวม "กฎเกณฑ์ (Rules)", "ความจริง (Facts)", หรือ "กรณีศึกษาในอดีต (Past Cases)" ที่ได้จากการสัมภาษณ์ผู้เชี่ยวชาญ
* **กลไกอนุมาน (Inference Engine):** โปรแกรมที่ทำหน้าที่ "คิดหาเหตุผล" โดยเอากฎเกณฑ์ในฐานความรู้มาตรวจสอบกับข้อมูลปัญหาที่ป้อนเข้าไป เพื่อสรุปออกมาเป็นคำแนะนำ (Recommendation)
* **ตัวอย่างการใช้:** ระบบอาจมีกฎว่า *IF (อัตราหนี้สิน > 50%) AND (รายได้ลดลง 2 ไตรมาสติด) THEN (แนะนำให้ปฏิเสธการขอสินเชื่อก้อนใหม่)* 

## การทำงานร่วมกันของสถาปัตยกรรม (Integration)

เมื่อผู้บริหารเผชิญปัญหา เขาจะป้อนคำถามหรือปรับค่าตัวแปรผ่าน **(3) User Interface** คำสั่งนั้นจะถูกส่งไปที่ **(2) Model Management** ซึ่งจะทำการเลือกโมเดลที่เหมาะสม หากโมเดลต้องการตัวเลขมาคำนวณ มันจะวิ่งไปดึงข้อมูลจาก **(1) Data Management** และหากจำเป็นต้องใช้กฎเกณฑ์พิเศษ มันจะถามไปยัง **(4) Knowledge-based System** เมื่อคำนวณเสร็จ ผลลัพธ์ทั้งหมดจะถูกวาดเป็นกราฟฟิกสวยงามกลับไปที่หน้าจอผู้ใช้อีกครั้ง ทั้งหมดนี้เกิดขึ้นภายในเวลาไม่กี่วินาที
