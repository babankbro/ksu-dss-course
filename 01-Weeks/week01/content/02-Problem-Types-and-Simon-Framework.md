# 2. ประเภทของปัญหาการตัดสินใจและกรอบกระบวนการของ Simon

การออกแบบและการนำระบบ DSS มาใช้ในองค์กรนั้น สิ่งสำคัญประการแรกคือการต้องระบุให้ได้ว่า "ปัญหา" ที่กำลังเผชิญอยู่นั้นเป็นปัญหาประเภทใด เพราะไม่ใช่ทุกปัญหาที่ต้องการ DSS นอกจากนี้ การเข้าใจ "กระบวนการ" ตัดสินใจจะช่วยให้นักพัฒนาระบบสามารถแทรกแซงและสนับสนุนได้อย่างถูกจุด

## 2.1 โครงสร้างของปัญหา (Problem Structuredness)

ตามกรอบแนวคิดของ Gorry และ Scott Morton ปัญหาการตัดสินใจสามารถแบ่งออกเป็น 3 ระดับตามระดับโครงสร้าง ซึ่งระดับโครงสร้างนี้จะเป็นตัวกำหนดว่าเราควรใช้เทคโนโลยีใดเข้ามาช่วย

### 1. ปัญหาแบบมีโครงสร้าง (Structured Problems)
* **ลักษณะ:** เป็นปัญหาที่มีความชัดเจนสูง มีกฎเกณฑ์ กระบวนการ ขั้นตอน และข้อมูลที่ต้องใช้ในการตัดสินใจถูกกำหนดไว้อย่างเป็นแบบแผน สามารถเขียนเป็นสมการคณิตศาสตร์ หรืออัลกอริทึมทางคอมพิวเตอร์ได้อย่างชัดเจน
* **การตัดสินใจ:** มักเกิดขึ้นบ่อย ซ้ำซาก (Routine)
* **บทบาทของเทคโนโลยี:** สามารถใช้ระบบคอมพิวเตอร์ทำงานแทนมนุษย์ได้เกือบ 100% (Automation) 
* **ตัวอย่าง:**
  - การคำนวณเงินเดือนและการหักภาษีพนักงาน
  - การหาจุดสั่งซื้อสินค้าเพิ่ม (Reorder Point) เมื่อสต็อกลดลงถึงระดับที่กำหนด
  - การอนุมัติการเบิกจ่ายงบประมาณที่ตรงตามระเบียบทุกประการ

### 2. ปัญหากึ่งมีโครงสร้าง (Semi-structured Problems)
* **ลักษณะ:** ปัญหาที่มีบางส่วนสามารถกำหนดกฎเกณฑ์หรือคำนวณได้ แต่ยังมีส่วนประกอบที่คลุมเครือ ต้องอาศัยประสบการณ์ วิจารณญาณ (Judgment) หรือความรู้สึกเชิงสัญชาตญาณ (Intuition) ของมนุษย์ร่วมด้วย
* **บทบาทของเทคโนโลยี:** **นี่คือจุดที่ DSS มีคุณค่าสูงสุด** DSS จะช่วยคำนวณและนำเสนอข้อมูลในส่วนที่เป็นรูปธรรม และปล่อยให้มนุษย์นำข้อมูลนั้นไปพิจารณาประกอบกับปัจจัยนามธรรม
* **ตัวอย่าง:**
  - **การอนุมัติสินเชื่อธุรกิจขนาดใหญ่:** ระบบสามารถคำนวณ Credit Score วิเคราะห์งบการเงิน อัตราส่วนทางการเงินต่างๆ (ส่วนที่มีโครงสร้าง) แต่ผู้จัดการต้องใช้วิจารณญาณประเมินวิสัยทัศน์ของผู้บริหาร ทิศทางอุตสาหกรรม หรือความเสี่ยงทางการเมือง (ส่วนที่ไม่มีโครงสร้าง) มาร่วมตัดสินใจ
  - **การวางแผนตารางการผลิต:** มีข้อจำกัดเรื่องเครื่องจักรและเวลาที่ชัดเจน แต่ต้องปรับเปลี่ยนตามความเร่งด่วนของลูกค้าคนสำคัญ
  - **การคัดเลือกบุคลากรเข้าทำงาน:** การกรองประวัติการศึกษา คะแนนสอบ (ส่วนมีโครงสร้าง) ผสมกับบุคลิกภาพ ทัศนคติจากการสัมภาษณ์ (ส่วนไม่มีโครงสร้าง)

### 3. ปัญหาแบบไม่มีโครงสร้าง (Unstructured Problems)
* **ลักษณะ:** เป็นปัญหาใหม่ที่ไม่เคยเกิดขึ้นมาก่อน เป้าหมายไม่ชัดเจน ข้อมูลไม่ครบถ้วน ไม่มีขั้นตอนการแก้ปัญหาที่เป็นแบบแผน หรือมีปัจจัยภายนอกที่ไม่แน่นอนเข้ามาเกี่ยวข้องสูง
* **บทบาทของเทคโนโลยี:** DSS จะเข้าไปช่วยในแง่ของการค้นหาข้อมูลเบื้องต้น การสร้างภาพรวม (Visualization) หรือการจำลองสถานการณ์หลายๆ รูปแบบ (Scenario Analysis) เพื่อให้ผู้บริหารเห็นภาพกว้าง
* **ตัวอย่าง:**
  - การตัดสินใจควบรวมกิจการ (M&A) ข้ามประเทศ
  - การรับมือกับวิกฤตการณ์ที่ไม่คาดฝัน เช่น โรคระบาดใหม่ (Pandemic)
  - การวางแผนกลยุทธ์ของบริษัทในอีก 10 ปีข้างหน้า

## 2.2 กรอบกระบวนการตัดสินใจของ Simon (Simon's Decision-Making Process)

การตัดสินใจไม่ใช่การกระทำเพียงครั้งเดียว (Not a single event) แต่เป็นกระบวนการ (Process) **Herbert Simon** ได้แบ่งกระบวนการตัดสินใจออกเป็น 4 ระยะ (Phases) ซึ่ง DSS สามารถเข้าไปมีบทบาทในแต่ละระยะได้แตกต่างกัน

### ระยะที่ 1: Intelligence (การค้นหาและรับรู้ปัญหา)
* **คำถามหลัก:** เกิดอะไรขึ้น? ปัญหาคืออะไร? หรือมีโอกาสอะไรซ่อนอยู่?
* **กิจกรรม:** การสแกนสภาพแวดล้อม การรวบรวมข้อมูล การระบุช่องว่างระหว่าง "สิ่งที่กำลังเป็นอยู่" (Current State) กับ "สิ่งที่ควรจะเป็น" (Desired State) 
* **บทบาทของเทคโนโลยี / DSS:**
  - ระบบแจ้งเตือน (Alert Systems) และ Exception Reporting
  - Data Warehouse และ Business Intelligence (BI) Dashboard เพื่อตรวจจับความผิดปกติ (เช่น ยอดขายตกในภาคเหนือ)
  - การใช้ Data Mining เพื่อหาความสัมพันธ์ที่ซ่อนอยู่ในข้อมูล

### ระยะที่ 2: Design (การสร้างและการประเมินทางเลือก)
* **คำถามหลัก:** มีทางเลือกอะไรบ้างในการแก้ปัญหานี้?
* **กิจกรรม:** การประดิษฐ์ พัฒนา และกำหนดรูปแบบของทางเลือกต่างๆ การสร้างตัวแบบ (Models) เพื่อใช้ประเมินผลลัพธ์ของแต่ละทางเลือก
* **บทบาทของเทคโนโลยี / DSS:**
  - การใช้แบบจำลองทางคณิตศาสตร์และสถิติ
  - การวิเคราะห์แบบ What-if (What-if Analysis) 
  - ซอฟต์แวร์จำลองสถานการณ์ (Simulation) เพื่อดูว่าถ้าเลือกวิธีนี้แล้ว ผลกระทบจะเป็นอย่างไร

### ระยะที่ 3: Choice (การตัดสินใจเลือก)
* **คำถามหลัก:** ทางเลือกใดดีที่สุด?
* **กิจกรรม:** การเปรียบเทียบทางเลือกทั้งหมดที่มี การประเมินข้อดีข้อเสีย (Trade-offs) ภายใต้เกณฑ์ที่กำหนด และตัดสินใจเลือกทางเลือกหนึ่ง (หรือหลายทางเลือกผสมกัน) ไปปฏิบัติจริง
* **บทบาทของเทคโนโลยี / DSS:**
  - ระบบ Optimization (เช่น การหาเส้นทางที่สั้นที่สุด หรือการลดต้นทุนให้ต่ำที่สุด)
  - การวิเคราะห์ความอ่อนไหว (Sensitivity Analysis) เพื่อดูว่าถ้าตัวแปรเปลี่ยนไป ทางเลือกนี้ยังดีที่สุดอยู่หรือไม่
  - เทคนิค Multi-Criteria Decision Analysis (MCDA) สำหรับการเลือกภายใต้เกณฑ์หลายข้อ

### ระยะที่ 4: Implementation (การนำไปปฏิบัติและติดตามผล)
* **คำถามหลัก:** ทำแล้วได้ผลตามที่คาดไว้หรือไม่?
* **กิจกรรม:** การแปลงการตัดสินใจให้เป็นการปฏิบัติจริง การติดตามผล (Monitoring) การเรียนรู้จากข้อผิดพลาด 
* **บทบาทของเทคโนโลยี / DSS:**
  - ระบบ Project Management และ Workflow Systems
  - ระบบรายงานผลย้อนกลับ (Feedback Systems)
  - หากผลลัพธ์ไม่เป็นไปตามคาด ระบบสามารถส่งข้อมูลกลับไปสู่ "ระยะ Intelligence" เพื่อเริ่มกระบวนการวิเคราะห์ปัญหาใหม่อีกครั้ง (Iterative Process)

### บทสรุปของกระบวนการ
กระบวนการของ Simon ไม่จำเป็นต้องเป็นเส้นตรง (Linear) เสมอไป ในโลกความเป็นจริง ผู้บริหารอาจเริ่มที่การรวบรวมข้อมูล (Intelligence) ไปสร้างทางเลือก (Design) แต่พบว่าข้อมูลไม่พอ จึงต้องย้อนกลับไปหาข้อมูลใหม่ (Intelligence) หรือขณะกำลังจะเลือก (Choice) อาจพบว่าทางเลือกยังมีไม่มากพอ จึงย้อนกลับไปสร้างทางเลือกเพิ่ม (Design) กระบวนการนี้มีการวนซ้ำ (Feedback Loops) อยู่ตลอดเวลา ซึ่ง DSS ที่ดีต้องมีความยืดหยุ่นรองรับการทำงานในลักษณะนี้ได้
