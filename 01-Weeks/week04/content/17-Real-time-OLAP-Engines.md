# 17. คลังข้อมูล OLAP แบบเรียลไทม์สุดขั้ว (Real-Time OLAP)

ระบบวิเคราะห์แบบ In-Memory หรือ ROLAP ทั่วไป อาจรันคำสั่งได้ใน 1 วินาที ซึ่งเพียงพอแล้วสำหรับรายงานผู้บริหาร แต่ในโลกของแอปพลิเคชันยุคใหม่ เช่น **Uber, Netflix, หรือแอปพลิเคชันส่งอาหาร** ข้อมูลไหลเข้ามาวินาทีละ 100,000 เหตุการณ์ และอัลกอริทึมต้องปรับราคาค่าส่ง (Surge pricing) ให้เสร็จภายใน 50 มิลลิวินาที! นี่คือหน้าที่ของ **Real-Time OLAP (RTOLAP)**

## 17.1 ข้อจำกัดของ OLAP ยุคเก่าต่อข้อมูลสตรีมมิ่ง
* ระบบ OLAP แบบเก่า (รวมถึง Cloud Data Warehouse) ถูกสร้างมาเพื่อรับข้อมูลแบบ Batch (โหลดทีละล้านบรรทัดทุกๆ ครึ่งชั่วโมง)
* ถ้าเราเอาท่อข้อมูลสด (Apache Kafka) ไปยิงคำสั่ง `INSERT` ทีละ 1 บรรทัดใส่ Data Warehouse รัวๆ... ระบบล็อกไฟล์จะพัง และจะเกิดคอขวดจนฐานข้อมูลล่ม

## 17.2 เหล่าฮีโร่แห่ง RTOLAP (Apache Druid, Pinot, ClickHouse)
เพื่อตอบโจทย์นี้ วงการซิลิคอนแวลลีย์ได้สร้างสายพันธุ์ฐานข้อมูล OLAP เฉพาะทางขึ้นมาใหม่:

1. **Apache Druid (ระบบรับข้อมูลแบบไร้รอยต่อ):**
   - เก่งมากในการรับข้อมูลจาก Kafka สดๆ 
   - วิธีแก้ปัญหา: Druid จะรับข้อมูลสดเก็บไว้ใน RAM ชั่วคราวก่อน (รันคำนวณจากตรงนี้ได้เลย) แล้วพอครบ 5 นาที มันจะบีบอัดข้อมูลก้อนนั้นแข็งตัวเป็นไฟล์ลงฮาร์ดดิสก์แบบเงียบๆ ทำให้สามารถ Query ข้อมูลสดและข้อมูลเก่าปนกันได้เนียนกริบ
2. **Apache Pinot (ระบบเสิร์ฟผู้ใช้งานนับล้านแบบพร้อมกัน):**
   - พัฒนาโดย LinkedIn
   - สมมติว่ามีผู้ใช้แอปพลิเคชัน 1 ล้านคน เปิดแอปฯ ขึ้นมาพร้อมกันเพื่อดู "ยอดวิวโปรไฟล์ของตัวเองในสัปดาห์นี้" (นี่คือ User-facing analytics)
   - Data Warehouse ปกติเจอยิงคิวรี 1 ล้านครั้งพร้อมกันจะล่มทันที แต่ Pinot ใช้สถาปัตยกรรมกระจายศูนย์ที่ซิงก์ดัชนี (Indexes) อย่างชาญฉลาด ทำให้เสิร์ฟคำตอบให้คนนับล้านได้ในเวลา < 0.1 วินาที
3. **ClickHouse (ความเร็วระดับฮาร์ดคอร์):**
   - เป็นระบบ ROLAP ที่ขึ้นชื่อเรื่องความเร็วเถื่อนที่สุด (Brute-force speed) เหมาะสำหรับดึงมาทำแดชบอร์ดมอนิเตอร์เซิร์ฟเวอร์หรือทราฟฟิกเว็บ

## 17.3 เมื่อใดควรใช้ RTOLAP?
อย่าใช้ RTOLAP ถ้ารายงานของคุณดูแค่สัปดาห์ละครั้ง เพราะมันมีค่าบำรุงรักษาเซิร์ฟเวอร์ที่แพงและดูแลยาก (ซับซ้อน)
แต่ **จงใช้ RTOLAP หากธุรกิจของคุณต้องการทำ:**
* การเฝ้าระวังความปลอดภัย (Fraud detection) บัตรเครดิตขณะรูด
* การปรับราคาค่าบริการแบบไดนามิก (Dynamic Pricing)
* แดชบอร์ดมอนิเตอร์เซิร์ฟเวอร์ล่ม (System Observability)
