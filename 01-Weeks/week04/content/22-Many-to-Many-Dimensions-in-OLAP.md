# 22. การรับมือความสัมพันธ์แบบ Many-to-Many ในโลก OLAP

กฎทองของการออกแบบ Star Schema คือ Dimension ต้องโยงเข้าหา Fact แบบ 1-to-Many เสมอ (เช่น ลูกค้า 1 คน มีบิลได้หลายใบ แต่ 1 ใบเสร็จ ต้องมีชื่อลูกค้าคนเดียว) แต่ในชีวิตจริง ความซับซ้อนระดับ Many-to-Many (M:N) นั้นหลีกเลี่ยงไม่ได้

## 22.1 ปัญหาโลกแตก Many-to-Many
**ตัวอย่างสุดคลาสสิก:**
* **โรงพยาบาล:** ผู้ป่วย 1 คน แอดมิท 1 ครั้ง (Fact) แต่... "มีหมอเจ้าของไข้ร่วมกัน 3 คน"
* **การเงิน:** บัญชีเงินฝาก 1 บัญชี (Fact) ... "มีชื่อผู้เปิดบัญชีร่วม (Joint Account) 2 คน (สามี-ภรรยา)"

ถ้าเราเอาชื่อหมอทั้ง 3 คน (หรือเจ้าของบัญชี 2 คน) ไปผูกกับ Fact ตรงๆ ยอดบิลค่ารักษาจะถูกคอมพิวเตอร์นับเบิ้ล 3 เท่า! (Double/Triple Counting) ซึ่งจะทำลายความน่าเชื่อถือของรายงานทันที

## 22.2 ทางแก้แบบ Bridge Table ในโมเดล OLAP
สถาปนิกข้อมูลจะแทรกตารางที่เรียกว่า **Bridge Table (ตารางสะพาน)** เข้าไปคั่นกลาง
* **โครงสร้าง:** 
  - `Fact_Admissions` โยงไปหา ➔ `Bridge_Doctor_Group`
  - `Bridge_Doctor_Group` โยงไปหา ➔ `Dim_Doctor` (รายชื่อหมอ)
* **กลไกการปันส่วน (Allocation Factor):**
  - ในตารางสะพาน จะมีการระบุ "น้ำหนัก (Weight)"
  - เช่น หมอหลัก (Primary) รับ 60%, หมอรอง (Secondary) รับคนละ 20%
  - เมื่อผู้ใช้ OLAP สั่งรันคำนวณ "รายได้ค่ารักษาแยกตามแพทย์" เอนจิ้น OLAP จะนำยอดเงิน 10,000 บาท ไปคูณกับ 60% หรือ 20% ก่อนที่จะโยนตัวเลขไปโชว์ในกราฟเสมอ

## 22.3 ความสามารถของเอนจิ้น OLAP ยุคใหม่ (DAX)
ในอดีต การทำ Bridge Table เป็นเรื่องยากและกินพลังประมวลผล แต่เครื่องมือ BI สมัยใหม่ (เช่น Power BI / Analysis Services) มีฟังก์ชันรองรับความสัมพันธ์แบบ Many-to-Many ในตัวแบบ Native

* **Cross-filter direction (Both):** เราสามารถตั้งค่าโมเดลให้เส้นความสัมพันธ์ (Relationship) ส่งแรงกระเพื่อมย้อนศร (Bi-directional filtering) ได้
* เมื่อผู้บริหารกดคลิกเลือกชื่อ "นายแพทย์ ก." ตารางสะพานจะทำการกรองหาบิลทั้งหมดที่มีชื่อแกเอี่ยวอยู่ และโชว์ผลลัพธ์ได้อย่างถูกต้อง โดยไม่ต้องเขียน SQL สลับซับซ้อน 

**ข้อควรระวัง:** การใช้ความสัมพันธ์แบบ Many-to-Many มากเกินไปในโมเดลเดียว จะทำให้เกิดความสับสนทางการคำนวณที่เรียกว่า "Ambiguity path (เส้นทางกำกวม)" ซึ่งเอนจิ้น OLAP อาจปฏิเสธการคำนวณ (Error) เพื่อป้องกันการตีความข้อมูลผิดพลาด
