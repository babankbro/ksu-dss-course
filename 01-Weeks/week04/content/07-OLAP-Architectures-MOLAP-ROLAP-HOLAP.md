# 7. สถาปัตยกรรมของ OLAP (MOLAP, ROLAP และ HOLAP)

การที่ระบบจะสามารถหมุนลูกบาศก์ข้อมูลและตอบสนองได้ในระดับเสี้ยววินาทีนั้น เบื้องหลังมีสถาปัตยกรรมการจัดเก็บข้อมูล 3 รูปแบบหลัก ที่องค์กรต้องเลือกใช้ให้ตรงกับความต้องการและงบประมาณ

## 7.1 MOLAP (Multidimensional OLAP)
* **หลักการทำงาน:** ข้อมูลถูกดึงออกจากฐานข้อมูลหลัก มาจัดเรียงใหม่ให้อยู่ในโครงสร้าง "ก้อนลูกบาศก์ (Cube Array)" แบบกรรมสิทธิ์เฉพาะ (Proprietary format) และทำการ "Pre-aggregate (บวกยอดรวมล่วงหน้า)" เอาไว้ทุกจุดตัด
* **ข้อดี:** 
  - เร็วแบบสายฟ้าแลบ (Blazing Fast) ตอบสนองแทบจะทันทีที่กดคลิก เพราะไม่ต้องรันสูตรคำนวณใหม่เลย
* **ข้อเสีย:** 
  - สิ้นเปลืองพื้นที่เก็บข้อมูลมหาศาล (Data Explosion)
  - ความสดของข้อมูลต่ำ เพราะต้องรอใช้เวลาตอนกลางคืนเพื่อ "ปั่น Cube"
  - ไม่สามารถทะลุลงไปดูรายละเอียดระดับบรรทัดบิล (Drill-through) ได้ลึกมากนัก
* **เหมาะสำหรับ:** รายงานผู้บริหารระดับสูงที่ยอดขายนิ่งแล้ว และต้องการความรวดเร็วในการนำเสนอ

## 7.2 ROLAP (Relational OLAP)
* **หลักการทำงาน:** ไม่มีการสร้างก้อนลูกบาศก์แยกต่างหาก ข้อมูลยังคงเก็บเป็นตาราง (Tables) ในระบบฐานข้อมูลปกติ (Star Schema) แต่ใช้ "เอนจิ้นคำนวณ SQL ระดับสูง" ในการบวกยอดสดๆ (On-the-fly) ทันทีที่ผู้ใช้กดคลิก
* **ข้อดี:** 
  - รองรับข้อมูลขนาดมหาศาลได้ไม่จำกัด (Scalability)
  - ข้อมูลสดใหม่เสมอ (Real-time / Near Real-time)
  - เจาะทะลุ (Drill-through) ลงไปดูยันระดับใบเสร็จรับเงินได้อย่างไร้รอยต่อ
* **ข้อเสีย:** 
  - ใช้เวลาในการประมวลผลนานกว่า (Query Latency) หากฮาร์ดแวร์ไม่แรงพอ หรือไม่ได้ทำ Index/Materialized Views ไว้
* **เหมาะสำหรับ:** ธุรกิจออนไลน์ ธุรกิจสตรีมมิ่ง หรือนักวิเคราะห์ระดับปฏิบัติการที่ต้องการดูข้อมูลสดล่าสุด

## 7.3 HOLAP (Hybrid OLAP)
* **หลักการทำงาน:** เป็นการพบกันครึ่งทาง นำข้อดีของทั้งสองระบบมารวมกัน
  - หากผู้บริหารขอดียอดรวมระดับสูง (เช่น ยอดขายรายปี, รายภูมิภาค) ระบบจะวิ่งไปดึงข้อมูลจาก **ก้อน Cube (MOLAP)** ที่ทำยอดสรุปรอไว้แล้ว เพื่อความรวดเร็ว
  - แต่ถ้าผู้บริหารเผลอกดเจาะลึกลงไป (Drill-down) จนถึงระดับยอดขายสาขาย่อยรายวัน システムจะสลับสวิตช์วิ่งไปดึงข้อมูลจาก **ตารางฐานข้อมูล (ROLAP)** มาตอบแทน
* **ข้อดี:** ได้ทั้งความเร็วในภาพรวม และได้ความลึกในระดับรายละเอียด
* **ข้อเสีย:** สถาปัตยกรรมซับซ้อนมาก (Complexity) ทีมไอทีต้องดูแลรักษาระบบสองแบบขนานกันไป และตั้งค่าการสับเปลี่ยนให้แม่นยำ

**วิวัฒนาการในปัจจุบัน:**
ด้วยความเร็วของ Cloud Data Warehouse (เช่น Snowflake, BigQuery) และ Columnar Storage สถาปัตยกรรม **ROLAP** ได้พัฒนาขึ้นจนมีความเร็วเทียบเท่าหรือแซงหน้า MOLAP ไปแล้ว ทำให้องค์กรยุคใหม่ค่อยๆ เลิกใช้ MOLAP แบบดั้งเดิม และหันมาเขียน SQL ชนกับฐานข้อมูลโดยตรงมากขึ้น
