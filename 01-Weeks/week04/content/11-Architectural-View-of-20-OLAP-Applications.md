# 11. มุมมองสถาปัตยกรรมและการเจาะลึก (Drill Path) ใน 20 แอปพลิเคชัน

เมื่อนำแนวคิด OLAP ไปประยุกต์ใช้ในอุตสาหกรรมต่างๆ "เส้นทางการสืบสวน (Decision Trail / Drill Path)" จะมีรูปแบบและจังหวะ (Rhythm) ที่เป็นเอกลักษณ์เฉพาะของสายอาชีพนั้นๆ 

*(นี่คือตัวอย่างเส้นทาง OLAP จาก 5 แอปพลิเคชันเด่น)*

## 1. Banking Spend (ระบบวิเคราะห์การใช้จ่ายบัตรเครดิต)
* **เป้าหมาย:** สังเกตพฤติกรรมการใช้จ่ายที่เปลี่ยนไปในช่วงเศรษฐกิจฝืดเคือง
* **เส้นทางการวิเคราะห์ (Drill Path):**
  1. `[Slice]` เลือก Segment = พนักงานเงินเดือนรายได้ต่ำ
  2. `[Pivot]` สลับแกน เอา "หมวดหมู่ร้านค้า (Merchant Category)" มาตัดกับ "จังหวัด"
  3. `[Drill-down]` เจาะลึกหมวดหมู่ร้านค้า "ซูเปอร์มาร์เก็ต" ลงไปดู "ประเภทการซื้อ" 
  4. **Insight:** พบว่ายอดรวมเท่าเดิม แต่สัดส่วนการซื้อ "ของสด" ลดลง และ "บะหมี่กึ่งสำเร็จรูป" เพิ่มขึ้นในแถบชานเมือง 

## 2. Telecommunications Usage (ระบบวิเคราะห์โทรคมนาคม)
* **เป้าหมาย:** ค้นหาสาเหตุที่คุณภาพสัญญาณลดลงในบางช่วงเวลา
* **เส้นทางการวิเคราะห์ (Drill Path):**
  1. `[Drill-down]` เจาะลึกมิติเวลา จาก `วัน (Day)` ➔ ทะลุลงไปถึงระดับ `ชั่วโมง (Hour)` 
  2. `[Dice]` ล็อกตัวกรองเฉพาะ `ชั่วโมงเร่งด่วน (17:00-19:00)` และ `เครือข่าย 5G`
  3. `[Roll-up]` รวบยอดมิติเสาสัญญาณ จากรายเสา ➔ ให้กลายเป็นยอดรวมระดับเขตกทม.
  4. **Insight:** พบว่าเขตสาทรมีการแย่งแบนด์วิดท์มหาศาล สถาปัตยกรรมระบบนี้ต้องรองรับ `Vectorized Execution` แบบเร็วพิเศษ เพราะการ Query ข้อมูลระดับชั่วโมงจากคนล้านคนกิน CPU มหาศาล

## 3. Supply Chain Delivery (ระบบวิเคราะห์การจัดส่งสินค้า)
* **เป้าหมาย:** ตรวจสอบคอขวดที่ทำให้การส่งของล่าช้า
* **เส้นทางการวิเคราะห์ (Drill Path):**
  1. `[Pivot]` นำ "รายชื่อซัพพลายเออร์" วางบนแกน X และ "เส้นทางเดินเรือ (Route)" วางบนแกน Y 
  2. `[Measure]` ดูค่า `Lead_Time` (จำนวนวันรอสินค้า)
  3. `[Drill-across]` นำกราฟ `Lead_Time` มาวางทาบกับกราฟ `ค่าใช้จ่ายขนส่งต่อชิ้น` 
  4. **Insight:** พบว่ามี 2 ซัพพลายเออร์ที่เลือกใช้เส้นทางอ้อม ทำให้ของมาช้ากว่า 3 วัน และยังมีต้นทุนขนส่งแพงกว่าปกติ (ระบบแจ้งเตือนให้นำไปเจรจาต่อรอง)

## 4. Hospital Operations (ระบบปฏิบัติการโรงพยาบาล)
* **เป้าหมาย:** จัดการความหนาแน่นของผู้ป่วย
* **เส้นทางการวิเคราะห์ (Drill Path):**
  1. `[Slice]` เลือกเฉพาะ `วันหยุดสุดสัปดาห์ (Weekend = True)`
  2. `[Drill-down]` เจาะจาก `โรงพยาบาลสาขาหลัก` ➔ `รายแผนกคลินิก`
  3. `[Drill-through]` กดทะลุตัวเลข 150 คนในแผนกฉุกเฉิน ➔ เข้าสู่รายชื่อคนไข้ (เวชระเบียน) เพื่อดูว่ามีอาการบาดเจ็บรุนแรงระดับใด (Triage)
  4. **ข้อระวัง:** ในหน้าจอ Drill-through จะต้องมีสถาปัตยกรรม Column-level Security (บทที่ 18 ของ Week 03) สวมทับไว้ เพื่อปิดบังชื่อคนไข้หากผู้ใช้งานไม่ใช่แพทย์

## 5. Education Analytics (ระบบวิเคราะห์ผลการศึกษา)
* **เป้าหมาย:** ตรวจสอบอัตราการสอบตก (Pass rate) ของนักศึกษา
* **เส้นทางการวิเคราะห์ (Drill Path):**
  1. `[Slice]` เลือกภาคการศึกษา `1/2026`
  2. `[Drill-down]` คณะวิศวกรรมศาสตร์ ➔ ภาควิชาคอมพิวเตอร์ ➔ รายวิชา "โครงสร้างข้อมูล"
  3. **คำเตือนทางสถิติ:** การใช้ OLAP ต้องระวังเรื่อง "Average of Averages" หากเอาคะแนนเฉลี่ยของเด็ก 3 ห้องมาบวกกันหาร 3 จะได้ตัวเลขที่ผิด ต้องคำนวณจาก (คะแนนรวมเด็กทั้งหมด) / (จำนวนเด็กทั้งหมด) เสมอ
