# 8. Modern OLAP: กลไกประมวลผลแนวตั้งและ Vectorization

เพื่อทำลายขีดจำกัดความเชื่องช้าของ ROLAP แบบดั้งเดิม สถาปัตยกรรมฮาร์ดแวร์และซอฟต์แวร์ของฐานข้อมูลเชิงวิเคราะห์ (Analytical Database) ในยุคหลังปี 2010 จึงถูกออกแบบใหม่หมดตั้งแต่รากฐาน

## 8.1 Columnar Storage (การจัดเก็บแบบแนวตั้ง)
ฐานข้อมูลดั้งเดิม (เช่น MySQL, PostgreSQL) บันทึกข้อมูลเป็นแนวราบ (Row-oriented) 1 บรรทัดเก็บข้อมูลลูกค้าครบทุกด้าน เหมาะกับการบันทึก (Insert)
* แต่ OLAP สมัยใหม่ (เช่น Amazon Redshift, Google BigQuery, ClickHouse) เก็บข้อมูลเป็นแนวดิ่ง (Column-oriented)
* **กลไกความเร็ว:** เมื่อนักวิเคราะห์สั่ง `SUM(net_sales)` ฐานข้อมูลจะวิ่งไปอ่านฮาร์ดดิสก์ **"เฉพาะไฟล์ที่เก็บคอลัมน์ net_sales"** โดยไม่ต้องเสียเวลาอ่านชื่อ นามสกุล ที่อยู่ ติดมาด้วย ทำให้ปริมาณ I/O (การอ่านเขียนดิสก์) ลดลงไปมากกว่า 90% ส่งผลให้ได้คำตอบเร็วขึ้นสิบเท่า
* **การบีบอัด (Compression):** พอข้อมูลประเภทเดียวกันเรียงต่อกัน (เช่น คำว่า 'Bangkok' เรียงติดกัน 10,000 บรรทัด) ระบบจะบีบอัดข้อมูลแบบ Run-Length Encoding กลายเป็น `Bangkok x 10,000` ช่วยประหยัดพื้นที่และอ่านเร็วขึ้นอีก

## 8.2 Vectorized Execution (การประมวลผลเป็นกลุ่ม)
* ฐานข้อมูลยุคเก่า อ่านข้อมูลขึ้นมาประมวลผล (บวก ลบ คูณ หาร) ทีละบรรทัด (Tuple-at-a-time) ซึ่ง CPU มีการสูญเสียเวลา Overhead สูงมาก
* **Modern OLAP:** ใช้วิธี Vectorized Execution คือการดูดข้อมูลขึ้นมาเป็นก้อนใหญ่ (เช่น ทีละ 10,000 บรรทัด) แล้วใช้คำสั่ง CPU ระดับฮาร์ดแวร์ (SIMD - Single Instruction, Multiple Data) กระหน่ำบวกเลข 10,000 บรรทัดให้เสร็จภายใน 1 รอบคำสั่งของ CPU ทำให้เร็วขึ้นอย่างก้าวกระโดด

## 8.3 Data Skipping และ Zone Maps
* ถ้านักวิเคราะห์สั่งคิวรี "ขอดูยอดขายปี 2026"
* แทนที่ฐานข้อมูลจะสแกนไฟล์ตั้งแต่ปี 2020 มาเรื่อยๆ ระบบ OLAP จะมี **Zone Maps** (แผนที่นำทาง) จดไว้ว่าไฟล์บล็อกไหนเก็บข้อมูลปีอะไร
* ระบบจะ **กระโดดข้าม (Skip)** ไฟล์ปี 2020-2025 ไปทั้งหมด และพุ่งไปอ่านเฉพาะไฟล์บล็อกของปี 2026 เท่านั้น

## 8.4 Embedded OLAP (การฝังเอนจิ้นไว้ในแอปพลิเคชัน)
แนวโน้มที่มาแรงที่สุดในปัจจุบันคือการใช้เครื่องมืออย่าง **DuckDB**
* สมัยก่อน หากพนักงานอยากรัน OLAP ต้องส่งคำขอวิ่งผ่านอินเทอร์เน็ตไปที่เซิร์ฟเวอร์
* DuckDB เป็นซอฟต์แวร์ OLAP ขนาดจิ๋ว ที่สามารถ "ฝัง (Embed)" ติดไปกับโปรแกรม Python หรือหน้าเว็บเบราว์เซอร์ได้เลย
* เมื่อผู้บริหารเปิด Dashboard บนโน้ตบุ๊ก ระบบจะดึงไฟล์ดิบมา แล้วใช้ CPU ของโน้ตบุ๊กผู้บริหารนั่นแหละ ประมวลผล OLAP สดๆ ทำให้ไม่ต้องจ่ายค่าเซิร์ฟเวอร์ Cloud แต่อย่างใด
