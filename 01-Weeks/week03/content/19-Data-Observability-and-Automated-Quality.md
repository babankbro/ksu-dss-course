# 19. การเฝ้าระวังข้อมูลและคุณภาพอัตโนมัติ (Data Observability)

"ท่อประปาแตก เราเห็นน้ำนองพื้น แต่ท่อข้อมูลแตก เราจะไม่เห็นอะไรเลยจนกว่าจะมีคนโวยวาย" นี่คือฝันร้ายที่สุดของ Data Engineer ในยุคที่ท่อส่งข้อมูล (Data Pipelines) มีความซับซ้อนโยงใยเป็นใยแมงมุม แนวคิดเรื่อง **Data Observability (ความสามารถในการสังเกตการณ์ข้อมูล)** จึงถือกำเนิดขึ้น

## 19.1 Data Observability คืออะไร?
มันคือการนำหลักการเฝ้าระวังระบบเซิร์ฟเวอร์ (System Monitoring) มาประยุกต์ใช้กับ "ตัวข้อมูล" โดยอาศัย 5 เสาหลัก ได้แก่:
1. **Freshness (ความสดใหม่):** ตารางอัปเดตตรงเวลาไหม? วันนี้ข้อมูลหยุดไหลตั้งแต่กี่โมง?
2. **Distribution (การกระจายตัว):** ค่าเฉลี่ยของข้อมูลเปลี่ยนไปจากปกติหรือเปล่า? (เช่น ปกติยอดรูดบัตรเฉลี่ย 1,000 บาท แต่วันนี้ยอดเฉลี่ยคือ 1 บาท... นี่คือสัญญาณอันตราย)
3. **Volume (ปริมาณ):** วันนี้ไฟล์ข้อมูลเข้ามากี่แถว? หดตัวลงหรือพุ่งปรี๊ดผิดปกติไหม?
4. **Schema (โครงสร้าง):** มีคนแอบไปเปลี่ยนชื่อคอลัมน์ หรือลบคอลัมน์ที่ระบบหน้าบ้านโดยไม่บอกทีม Data หรือไม่?
5. **Lineage (สายระแหรก):** ถ้าท่อนี้แตก มันจะลามไปพังที่รายงานผู้บริหารตัวไหนบ้าง?

## 19.2 Machine Learning เข้ามาช่วยจับผิด
ในยุคก่อน Data Engineer ต้องเขียนกฎเตือนเอง (เช่น ถ้าจำนวนบรรทัด < 100 ให้ส่ง Alert) แต่วิธีนี้ทำไม่ได้จริงเมื่อเรามีตารางเป็นพันๆ ตาราง
* **Automated Anomaly Detection:** เครื่องมือสมัยใหม่ (เช่น Monte Carlo, Databand) จะใช้ Machine Learning เข้ามาสแกนข้อมูลย้อนหลัง 30 วัน เพื่อเรียนรู้ "พฤติกรรมปกติ (Baseline)" ของข้อมูล 
* หาก AI พบว่า "ปกติตารางนี้วันเสาร์ยอดขายจะตกอยู่แล้ว ไม่ต้องแจ้งเตือน" มันก็จะไม่รบกวนวิศวกร 
* แต่ถ้า AI พบว่า "ทำไมอัตราการเป็น Null ในคอลัมน์อีเมล พุ่งจาก 1% เป็น 50% กะทันหัน" มันจะส่งข้อความแจ้งเตือนเข้า Slack ของทีมวิศวกรทันทีก่อนที่ Dashboard จะอัปเดตให้เจ้านายเห็น

## 19.3 การสกัดกั้นข้อมูลเสีย (Circuit Breakers)
เมื่อพบความผิดปกติ ระบบ Observability ที่ดีจะสามารถสับสวิตช์เบรกเกอร์ได้
* **หยุดท่อทันที (Halt Pipeline):** ป้องกันไม่ให้ "ข้อมูลขยะ" ไหลเข้าไปปนกับข้อมูลดีใน Data Warehouse 
* มันดีกว่าการยอมให้รายงานออกไปผิดๆ เพราะความเชื่อมั่น (Trust) สร้างยากแต่ทำลายง่าย การขึ้นป้ายว่า "ข้อมูลวันนี้กำลังปรับปรุง" ย่อมดีกว่าการปล่อยยอดขายผิดๆ ไปให้ AI รันสั่งซื้อของผิดพลาด
