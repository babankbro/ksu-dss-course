# 20. ปฏิวัติการปั้นข้อมูลด้วย dbt (Data Build Tool)

เมื่อเราย้ายจากยุค ETL (ดูด-แปลง-โหลด) มาสู่ยุค ELT (ดูด-โหลด-แปลง) การ "แปลงข้อมูล (Transformation)" ภายใน Cloud Data Warehouse จึงกลายเป็นงานหลักของนักวิเคราะห์ข้อมูล (Data Analyst / Analytics Engineer) และเครื่องมือที่ปฏิวัติวงการนี้คือ **dbt**

## 20.1 ทำไมต้องใช้ dbt?
ในอดีต การปั้นตาราง (Transform) มักใช้วิธีเขียน Stored Procedure ภาษา SQL ยาว 2,000 บรรทัด ทิ้งไว้ในฐานข้อมูล 
* **ปัญหา:** โค้ดอ่านยาก ทดสอบไม่ได้ (Un-testable) เวลาพังก็หาบัคไม่เจอ และทำงานซ้ำซ้อนกัน
* **ทางแก้ด้วย dbt:** นำหลักการวิศวกรรมซอฟต์แวร์ที่ดีมาใช้กับการเขียน SQL

## 20.2 หลักการทำงานของ dbt
dbt ทำหน้าที่เป็นตัวจัดการคิวรี (Query Manager) บน Data Warehouse โดยที่ **ไม่ได้ดึงข้อมูลออกมาเลย** (ดึงแต่คำสั่ง)

1. **Modular SQL (หั่นเป็นชิ้นเล็กๆ):**
   - แทนที่จะเขียนคิวรียาวเหยียด dbt บังคับให้เราเขียน SQL สั้นๆ เป็นโมดูล (ชิ้นส่วน) เช่น `model_customers`, `model_orders` 
   - โมดูลหนึ่งสามารถเรียกใช้อีกโมดูลหนึ่งได้ผ่านฟังก์ชัน `{{ ref('model_orders') }}` 
   - ทำให้เมื่อตรรกะคำนวณยอดขายเปลี่ยน เราแก้แค่ไฟล์เดียว (Reusability)

2. **Automated Testing (ทดสอบอัตโนมัติ):**
   - dbt ให้เราเขียนในไฟล์ YAML ได้เลยว่า `คอลัมน์ order_id ห้ามเป็นค่าว่าง และต้องไม่ซ้ำ`
   - เมื่อกดรัน dbt จะแอบสร้างคิวรีไปตรวจฐานข้อมูลให้ ถ้าเจอบรรทัดไหนซ้ำ มันจะเตือนทันที (Data Quality check ในตัว)

3. **Documentation (เอกสารคู่มือเสกได้):**
   - dbt สามารถอ่านคำอธิบายในไฟล์ที่เราเขียน แล้วเจเนอเรตหน้าเว็บ Document ที่อธิบายความหมายของทุกตาราง ทุกคอลัมน์ ออกมาอัตโนมัติ

4. **Lineage Graph (กราฟความเชื่อมโยง):**
   - dbt อ่านฟังก์ชัน `ref()` แล้ววาดกราฟตาข่ายให้ดูเลยว่า ตาราง `Fact_Sales_Final` เกิดจากการเอาตารางกี่ใบมาผสมกัน

## 20.3 จุดเปลี่ยนของวงการ Analytics
dbt ทำให้เกิดตำแหน่งใหม่ที่เรียกว่า **Analytics Engineer** ซึ่งเป็นลูกผสมระหว่าง Data Analyst (คนที่เก่งธุรกิจและ SQL) กับ Data Engineer (คนที่เก่งการทำ Version Control แบบ Git) 
* ทุกการแก้ไขสูตรคำนวณจะต้องถูก Commit ลง Git และมีคนตรวจทาน (Code Review) เหมือนการสร้างซอฟต์แวร์
* การเปลี่ยนผ่านนี้ทำให้ท่อส่งข้อมูลขององค์กรมีความเป็นระบบ (Engineering Rigor) และลดการสร้างตารางขยะที่ไม่มีใครดูแลได้อย่างมหาศาล
