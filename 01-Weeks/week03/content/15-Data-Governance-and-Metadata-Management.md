# 15. ธรรมาภิบาลข้อมูลและการจัดการข้อมูลอธิบายข้อมูล (Data Governance & Metadata Management)

การสร้าง Data Warehouse ที่มีโครงสร้างดีเยี่ยมก็ยังสามารถกลายเป็นสุสานข้อมูลได้ หากไม่มีใครในองค์กรรู้ว่า "ข้อมูลนี้คืออะไร ใครดูแล และเชื่อถือได้แค่ไหน" นี่คือเหตุผลที่โครงการข้อมูลขนาดใหญ่ต้องมีธรรมาภิบาลข้อมูล (Data Governance)

## 15.1 ตำแหน่งผู้พิทักษ์ข้อมูล (Data Stewards)
ข้อมูลไม่ได้ดูแลตัวเอง มันต้องการเจ้าของ (Ownership)
* **Data Owner (เจ้าของข้อมูล):** มักเป็นผู้บริหารสายธุรกิจ เช่น ผู้อำนวยการฝ่ายขาย เป็นผู้มีอำนาจตัดสินใจว่า "ยอดขายสุทธิ" ในบริษัทเราต้องมีนิยามการคำนวณอย่างไร และใครมีสิทธิ์ดูได้บ้าง
* **Data Steward (ผู้พิทักษ์ข้อมูล):** เป็นคนทำงานที่เข้าใจทั้งธุรกิจและไอที หน้าที่คือคอยสอดส่องว่าข้อมูลที่ไหลเข้ามาใน Warehouse ยังคงความสะอาดตามนิยามที่เจ้านาย (Owner) กำหนดไว้หรือไม่ และเป็นคนตอบคำถามชาวบ้านเวลาคนสงสัยว่าตารางนี้ดึงคอลัมน์ไหนไปใช้

## 15.2 แคตตาล็อกข้อมูล (Data Catalog)
เมื่อ Data Warehouse มีจำนวนตารางเกิน 1,000 ตาราง นักวิเคราะห์ (Data Analyst) จะเริ่มหาข้อมูลไม่เจอ
* องค์กรจึงต้องติดตั้ง **Data Catalog (พจนานุกรมข้อมูลส่วนกลาง)** เช่นซอฟต์แวร์ Alation หรือ Collibra
* หน้าที่คือเป็น "Google Search ภายในองค์กร" ให้พิมพ์ค้นหาคำว่า "ลูกค้า" ระบบจะลิสต์ตารางทั้งหมดที่มีคำนี้ พร้อมอธิบายว่าแต่ละคอลัมน์หมายถึงอะไร ใครเป็นคนสร้าง ตารางนี้ดึงอัปเดตล่าสุดกี่โมง
* นี่คือการยกระดับ **Metadata (ข้อมูลอธิบายข้อมูล)** ให้กลายเป็นสินทรัพย์ที่มีค่าที่สุดของบริษัท

## 15.3 สายระแหรกข้อมูล (Data Lineage)
ความสามารถที่เจ๋งที่สุดของ Data Catalog ยุคใหม่คือ Data Lineage หรือการสืบสาวราวเรื่อง:
* เมื่อผู้บริหารเปิด Dashboard แล้วพบว่ายอดขายตกผิดปกติ เขาต้องการรู้ว่า "ตัวเลขนี้คำนวณผิดหรือขายไม่ได้จริงๆ?"
* Data Lineage จะวาดกราฟเส้นโยงให้ดูเลยว่า: `กราฟแท่งบนหน้าจอ` ⬅️ ดึงมาจาก `ตาราง Fact_Sales` ⬅️ ดึงมาจาก `ท่อ ETL ชื่อ Sales_Job` ⬅️ ดึงมาจาก `ตาราง POS ฝั่ง OLTP`
* หากท่อ ETL เป็นสีแดง (Error) ผู้บริหารจะรู้ทันทีว่าตัวเลขไม่ได้ตก แต่โปรแกรมดูดข้อมูลพังต่างหาก

## 15.4 นโยบายการกำจัดข้อมูล (Data Retention Policy)
ธรรมาภิบาลครอบคลุมไปถึง "การลบ" ด้วย
* Data Warehouse ไม่ใช่ถังขยะที่จะเก็บทุกอย่างไปตลอดกาล
* ตามกฎหมาย PDPA ข้อมูลส่วนบุคคลบางอย่างต้องถูกลบหรือทำให้เป็นนิรนาม (Anonymized) เมื่อลูกค้าปิดบัญชีไปแล้ว 5 ปี 
* การจัดการ Lifecycle ของข้อมูลเหล่านี้ เป็นหน้าที่ของคณะกรรมการ Data Governance ที่ต้องตั้งกฎเกณฑ์ให้ Data Engineer ไปเขียนโปรแกรมลบอัตโนมัติ
