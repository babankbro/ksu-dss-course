# 10. วิวัฒนาการจาก Warehouse สู่ Mart, Lake และ Lakehouse

โลกของข้อมูลไม่ได้หยุดนิ่งแค่ Data Warehouse เมื่อองค์กรต้องรับมือกับข้อมูลที่แปลกประหลาดและใหญ่ขึ้น สถาปัตยกรรมการจัดเก็บจึงต้องวิวัฒนาการตามไปด้วย

## 10.1 Data Mart (คลังข้อมูลเฉพาะกิจ)
* **ความหมาย:** Data Mart คือ Data Warehouse ขนาดย่อส่วน ที่ดึงข้อมูลเฉพาะบางเรื่องออกไปให้แผนกใดแผนกหนึ่งใช้โดยเฉพาะ 
* **ตัวอย่าง:** HR Data Mart จะมีเฉพาะตารางเงินเดือน ขาด ลา มา สาย เพื่อให้ทีม HR เปิดดูได้รวดเร็ว โดยไม่ต้องไปวิ่งแย่งทรัพยากรฐานข้อมูลกับฝ่ายขาย
* **จุดเด่น:** เร็ว โฟกัสเฉพาะแผนก และปลอดภัย (เพราะแยกวงออกมา)
* **ความเสี่ยง:** หากองค์กรสร้าง Data Mart ขึ้นมาเองสะเปะสะปะโดยไม่ดึงจาก Data Warehouse กลาง จะเกิดปัญหา "ไซโล (Silo)" และกลับไปสู่ปัญหาความจริงหลายเวอร์ชันเหมือนเดิม

## 10.2 Data Lake (ทะเลสาบข้อมูล)
* **ปัญหาของ Warehouse:** Data Warehouse บังคับว่าเราต้องรู้ "โครงสร้าง (Schema)" ล่วงหน้า ต้องรู้ว่าจะมีกี่คอลัมน์ แล้วถ้าข้อมูลเป็น ภาพถ่าย เสียงสนทนา หรือวิดีโอล่ะ? Warehouse เก็บไม่ได้!
* **ความหมาย:** Data Lake คือที่เก็บข้อมูลดิบราคาถูกมหาศาล ที่รับของทุกอย่าง (Structured, Semi-structured เช่น JSON, และ Unstructured เช่น วิดีโอ) โดย **"โยนลงไปก่อน ค่อยไปคิดโครงสร้างทีหลัง (Schema-on-read)"**
* **ผู้ใช้งานหลัก:** Data Scientist ที่ต้องการขุดทองหาความสัมพันธ์แปลกๆ จากข้อมูลดิบเพื่อสร้าง Machine Learning
* **ความเสี่ยง:** หากโยนข้อมูลลงไปโดยไม่มีพจนานุกรมกำกับ (Metadata Catalog) ทะเลสาบจะเน่าเสียกลายเป็น **"Data Swamp (หนองน้ำข้อมูล)"** ที่ไม่มีใครรู้ว่าไฟล์นี้คืออะไร ใครเป็นคนสร้าง และเอาไปใช้ทำอะไรได้บ้าง

## 10.3 Data Lakehouse (ลูกผสมแห่งอนาคต)
* **ปัญหา:** องค์กรต้องจ่ายเงิน 2 ต่อ คือสร้าง Data Lake ให้ Data Scientist รันโมเดล และดูดข้อมูลที่สะอาดแล้วไปใส่ Data Warehouse ให้ผู้บริหารดูรายงาน
* **ความหมาย:** Data Lakehouse คือสถาปัตยกรรมแห่งทศวรรษใหม่ (เช่น Databricks, Apache Iceberg) ที่พยายามรวมข้อดีของทั้ง 2 โลกเข้าด้วยกัน
  - **Storage:** เก็บข้อมูลลงบน Storage ราคาถูกของ Cloud เหมือน Data Lake (เป็นไฟล์ดิบ)
  - **Compute & Governance:** นำเทคโนโลยี Transaction (ACID) และ SQL มาครอบทับไฟล์ดิบนั้นไว้ ทำให้ผู้บริหารสามารถ Query รายงานได้อย่างรวดเร็วและปลอดภัยเหมือน Data Warehouse
* **จุดเด่น:** ระบบเดียวจบทั้งองค์กร ทำได้ทั้งระบบ AI และ BI ในที่เดียวกัน

การเลือกสถาปัตยกรรม ขึ้นอยู่กับวุฒิภาวะทางข้อมูล (Data Maturity) ขององค์กร ว่ามีความพร้อมและทรัพยากรบุคลากรมากน้อยเพียงใด
