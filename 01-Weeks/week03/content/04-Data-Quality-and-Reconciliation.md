# 4. คุณภาพข้อมูลและการกระทบยอด (Data Quality & Reconciliation)

ในฐานะวิศวกรข้อมูล (Data Engineer) เราไม่สามารถเชื่อใจระบบต้นทาง (Source Systems) ได้เลย ระบบขายหน้าร้านอาจพัง พนักงานอาจพิมพ์ผิด หรือเครือข่ายอาจหลุด ดังนั้นท่อส่งข้อมูลต้องมีด่านตรวจคนเข้าเมืองที่เข้มงวด

## 4.1 มิติของคุณภาพข้อมูล (Data Quality Dimensions)
การจะบอกว่าข้อมูล "มีคุณภาพ" ต้องสร้างกติกาที่คอมพิวเตอร์ทดสอบได้ (Testable Rules):

1. **Completeness (ความครบถ้วน):**
   - *กฎ:* คอลัมน์ `order_id` และ `order_date` ห้ามมีค่าว่าง (Null) เด็ดขาด
2. **Uniqueness (ความไม่ซ้ำซ้อน):**
   - *กฎ:* ห้ามมีหมายเลขใบเสร็จ `order_line_id` ซ้ำกันในระบบเดียวกัน ถ้าระบบเจอค่าซ้ำ ต้องตัดทิ้งหรือแจ้งเตือน
3. **Validity (ความสมเหตุสมผล):**
   - *กฎ:* จำนวนสินค้า (Quantity) ต้องมากกว่า 0 เสมอ และส่วนลด (Discount) ต้องอยู่ระหว่าง 0 ถึง 100%
4. **Consistency (ความสอดคล้องกัน):**
   - *กฎ:* สมการคณิตศาสตร์ต้องเป๊ะ `(จำนวนสินค้า × ราคาต่อหน่วย) - ส่วนลด = ยอดสุทธิ` ถ้าบวกลบแล้วไม่ตรงกัน แปลว่าข้อมูลมีปัญหา
5. **Timeliness (ความทันเวลา):**
   - *กฎ:* ข้อมูลจากสาขาต้องเดินทางมาถึงคลังข้อมูลส่วนกลางภายใน 30 นาที
6. **Referential Integrity (ความสมบูรณ์อ้างอิง):**
   - *กฎ:* ทุกรหัสสินค้า (`product_key`) ที่อยู่ในตารางยอดขาย จะต้องสามารถเปิดหาชื่อสินค้าได้ในตารางสินค้า (Dimension) ห้ามมีสินค้ายอดมนุษย์ลอยเข้ามาโดยไม่มีชื่อ

**การจัดการเมื่อเจอข้อมูลผิด (Actions):** 
เมื่อตรวจเจอข้อมูลที่สอบตกกติกาเหล่านี้ ระบบอาจจะเลือกทำ 1 ใน 3 อย่าง:
- *Reject (ทิ้ง):* เตะข้อมูลทิ้งไปเลย (ไม่แนะนำ เพราะตัวเลขรวมจะหาย)
- *Quarantine (กักกัน):* เอาข้อมูลไปพักไว้ในตารางกักโรค แล้วส่งอีเมลแจ้งคนมาดู
- *Default/Unknown:* ยอมให้ผ่านไปได้ แต่แปะป้ายว่ารหัสสินค้านี้ "Unknown (ไม่ทราบชื่อ)" เพื่อให้ยอดเงินรวมยังคงถูกต้อง

## 4.2 การกระทบยอด (Reconciliation)
เพื่อเป็นหลักฐานยืนยันว่าท่อส่งข้อมูล (ETL) ทำงานไม่พลาด เราต้องทำ Reconciliation หรือ "การตรวจนับยอด" ระหว่างต้นทางกับปลายทาง ทุกเช้า:

* **Row Count Check:** จำนวนบรรทัดจากระบบต้นทาง = จำนวนบรรทัดที่โหลดเข้าคลังสำเร็จ + จำนวนบรรทัดที่ถูกกักกัน (Quarantined)
* **Sum of Money Check:** ยอดเงินรวมในระบบ POS หน้าร้าน = ยอดเงินรวมใน Data Warehouse
* **Distinct Transaction Check:** จำนวนบิลที่ออก = จำนวนบิลที่เก็บในระบบ

การเขียนสมการควบคุม (Control Equations) เหล่านี้ฝังไว้ในระบบ จะช่วยให้ทีมงานหลับสบายในตอนกลางคืน หากเช้าวันไหนตัวเลข 2 ฝั่งไม่เท่ากัน ระบบจะส่งข้อความแจ้งเตือน (Alert) ให้รีบแก้ไขก่อนที่ผู้บริหารจะเปิด Dashboard ขึ้นมาดู
