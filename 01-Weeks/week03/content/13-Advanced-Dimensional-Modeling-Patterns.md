# 13. รูปแบบจำลองมิติขั้นสูง (Advanced Dimensional Modeling Patterns)

การทำ Star Schema แบบพื้นฐานอาจตอบโจทย์ธุรกิจทั่วไปได้ แต่ในชีวิตจริง ธุรกิจมักมีความซับซ้อนที่ทะลุกรอบมาตรฐาน สถาปนิกข้อมูลจึงต้องใช้รูปแบบขั้นสูงเพื่อแก้ปัญหาเหล่านี้

## 13.1 Factless Fact Tables (ตารางข้อเท็จจริงที่ไม่มีตัวเลข)
* **ปัญหา:** Fact Table ปกติจะมีตัวเลข Measure (เช่น ยอดเงิน, จำนวน) แต่ถ้าเหตุการณ์นั้น "ไม่มีตัวเลขให้วัด" แต่เรายังอยากบันทึกว่ามันเกิดขึ้นล่ะ?
* **แนวคิด:** Factless Fact Table คือตาราง Fact ที่มีเฉพาะ Foreign Keys โยงไปหา Dimension ต่างๆ แต่ไม่มีคอลัมน์ตัวเลขอยู่เลย (หรืออาจมีแค่คอลัมน์ `count` = 1)
* **ตัวอย่างการใช้งาน:**
  1. **Event Tracking:** ตาราง "การเข้าเรียนของนักศึกษา" มีแค่ `วัน_key`, `นักศึกษา_key`, `วิชา_key`, `ห้องเรียน_key` ไม่มีตัวเลขอะไรให้บวก แต่ใช้นับจำนวนแถว (Count rows) ว่านักศึกษาขาดเรียนกี่ครั้ง
  2. **Coverage Tracking:** ตาราง "โปรโมชันที่เสนอให้ลูกค้า" บันทึกว่าลูกค้าคนนี้ได้รับแคตตาล็อกสินค้าอะไรไปบ้าง แม้เขาจะยังไม่ได้ซื้อก็ตาม (เพื่อใช้วิเคราะห์เทียบกับสิ่งที่ซื้อจริง)

## 13.2 Bridge Tables (ตารางสะพาน)
* **ปัญหา:** ความสัมพันธ์ระหว่าง Dimension กับ Fact ปกติจะเป็น 1-to-Many (ลูกค้า 1 คน มีได้หลายบิล) แต่ถ้าความสัมพันธ์เป็น **Many-to-Many** ล่ะ? เช่น บัญชีเงินฝากร่วมที่มีเจ้าของ 3 คน (นาย A, นาย B, นาย C) ยอดเงิน 10,000 บาทนี้จะผูกกับใคร? ถ้านำยอดเงินไปใส่ให้ทั้ง 3 คน ยอดรวมจะกลายเป็น 30,000 บาททันที (Double Counting)
* **แนวคิด:** การใช้ Bridge Table หรือตารางสะพาน มาคั่นกลางระหว่าง Dimension (ลูกค้า) และ Fact (บัญชีเงินฝาก)
* **การทำงาน:** ใน Bridge Table จะมีการกำหนด "น้ำหนัก (Weight Factor)" เช่น แบ่งให้นาย A 50%, นาย B 25%, นาย C 25% เมื่อสืบค้นยอดรวม โปรแกรมจะเอายอด 10,000 บาทไปคูณน้ำหนักก่อน ทำให้ยอดรวมระดับองค์กรยังคงถูกต้องเป๊ะที่ 10,000 บาทเสมอ

## 13.3 Role-playing Dimensions (ตารางมิติแบบเล่นหลายบทบาท)
* **ปัญหา:** ในตารางยอดขาย 1 บิล อาจมี "วันที่" เข้ามาเกี่ยวข้องหลายวัน เช่น `Order_Date`, `Ship_Date`, `Delivery_Date` เราต้องสร้างตาราง `Dim_Date` 3 ตารางเลยหรือไม่?
* **แนวคิด:** ไม่ต้องสร้างซ้ำ เราใช้ `Dim_Date` แค่ตารางเดียว (ตารางกายภาพเดียวในฐานข้อมูล) แต่นำมาสร้าง **"View"** หรือนามแฝง (Alias) 3 ชื่อ
* **การทำงาน:** เราจะโยง Foreign Key ทั้ง 3 ตัวใน Fact Table ชี้ไปที่ตาราง `Dim_Date` ตารางเดียวกัน การทำเช่นนี้ทำให้เราสามารถสืบค้นรายงานแบบ "แสดงยอดสั่งซื้อเปรียบเทียบกับยอดจัดส่งในเดือนเดียวกัน" ได้อย่างสมบูรณ์แบบ
