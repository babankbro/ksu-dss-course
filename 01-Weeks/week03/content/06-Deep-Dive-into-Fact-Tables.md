# 6. เจาะลึกตารางข้อเท็จจริง (Fact Tables)

ในการทำ Dimensional Modeling ตารางจะถูกแบ่งเป็น 2 ประเภทหลัก คือ Fact Table (ตารางข้อเท็จจริง) และ Dimension Table (ตารางมิติ) ในบทนี้เราจะมาเจาะลึกตัวเอกของเรื่อง นั่นคือ **Fact Table**

## 6.1 โครงสร้างของ Fact Table
Fact Table เปรียบเสมือนสมุดจดบัญชีที่บันทึก "เหตุการณ์ (Events)" ที่เกิดขึ้นในธุรกิจ โครงสร้างของมันประกอบด้วย 2 ส่วนหลัก:
1. **Foreign Keys (คีย์ต่างด้าว):** รหัสที่ชี้ไปยังตาราง Dimension เพื่อบอกบริบท เช่น `date_key`, `customer_key`, `product_key`
2. **Measures (ตัวชี้วัด):** ตัวเลขเชิงปริมาณที่ใช้คำนวณ เช่น `quantity` (จำนวนชิ้น), `net_amount` (ยอดสุทธิ)

*ข้อสังเกต:* Fact Table มักจะมีลักษณะ "ผอมแต่ยาวมาก" (มีแค่คอลัมน์ตัวเลข แต่มีจำนวนบรรทัดหลายร้อยล้านบรรทัด)

## 6.2 ประเภทของ Measures (ความสามารถในการนำมาบวกกัน)
สถาปนิกต้องระวังให้ดีว่า ตัวเลขใน Fact Table นั้น นำมาบวกกัน (Sum) ได้หรือไม่:
* **Fully Additive (บวกได้ทุกมิติ):** เช่น `ยอดขาย (Sales Amount)` สามารถเอามาบวกกันข้ามลูกค้า ข้ามวัน ข้ามสินค้า ได้อย่างปลอดภัย
* **Semi-additive (บวกได้บางมิติ):** เช่น `ยอดเงินคงเหลือในบัญชี (Account Balance)` เราสามารถบวกยอดคงเหลือของนาย A กับนาย B เพื่อหาเงินเก็บของทั้งหมู่บ้านได้ แต่เรา **ห้าม** เอายอดคงเหลือของนาย A ในวันจันทร์ ไปบวกกับวันอังคาร เพราะมันจะกลายเป็นตัวเลขที่ไม่มีความหมาย (บวกข้ามมิติเวลาไม่ได้)
* **Non-additive (บวกไม่ได้เลย):** เช่น `เปอร์เซ็นต์ส่วนลด (Discount Percentage)` หรือ `อุณหภูมิ` ห้ามนำมาบวกกันเด็ดขาด หากต้องการคำนวณส่วนลดรวม ต้องเก็บเป็นจำนวนเงิน (Discount Amount) แล้วค่อยเอาไปหารทีหลัง

## 6.3 ประเภทของ Fact Table
เพื่อให้รองรับธุรกิจได้ทุกรูปแบบ Fact Table แบ่งออกเป็น 3 ประเภทหลัก:

1. **Transaction Fact (ตารางเหตุการณ์รายครั้ง):**
   - *ทำงานอย่างไร:* บันทึก 1 บรรทัด เมื่อมีเหตุการณ์เกิดขึ้น 1 ครั้ง (เช่น รูดบัตรเครดิต, สแกนสินค้าผ่านเครื่องคิดเงิน)
   - *ลักษณะ:* ถ้าไม่มีการขาย ก็ไม่มีบรรทัดเพิ่ม ใช้วัดกระแส (Flow) ของธุรกิจ

2. **Periodic Snapshot Fact (ตารางสรุปสถานะตามรอบ):**
   - *ทำงานอย่างไร:* การถ่ายภาพสถานะ (Snapshot) ณ เวลาใดเวลาหนึ่งอย่างสม่ำเสมอ เช่น สรุปยอดคงคลัง (Inventory) ทุกเที่ยงคืน
   - *ลักษณะ:* แม้ว่าวันนี้ไม่มีการขายสินค้าเลย ระบบก็จะบันทึก 1 บรรทัดเพื่อบอกว่า "สินค้า A คงเหลือ 100 ชิ้น ณ วันที่..." ใช้วัดระดับ (Level) หรือคลังสะสม

3. **Accumulating Snapshot Fact (ตารางสะสมตามก้าวหน้า):**
   - *ทำงานอย่างไร:* ใช้จับตากระบวนการที่มี "จุดเริ่มต้น" และ "จุดสิ้นสุด" ชัดเจน เช่น กระบวนการสั่งซื้อออนไลน์ (กดสั่ง -> จ่ายเงิน -> เตรียมของ -> จัดส่ง -> ได้รับของ)
   - *ลักษณะ:* 1 บรรทัดคือคำสั่งซื้อ 1 ออเดอร์ โดยในบรรทัดนั้นจะมีคอลัมน์วันที่ 5 คอลัมน์ (ตามขั้นตอน) เมื่อกระบวนการขยับ ระบบจะกลับมา **อัปเดต (Update)** บรรทัดเดิมเพื่อเติมวันที่ลงไปเรื่อยๆ ใช้เพื่อวัดระยะเวลา (Lead Time) ว่าจากสั่งถึงส่งใช้เวลากี่วัน
