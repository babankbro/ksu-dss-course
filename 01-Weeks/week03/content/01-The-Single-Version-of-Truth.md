# 1. ปัญหาความจริงหลายเวอร์ชัน (The Single Version of Truth)

ในโลกการทำงานจริงขององค์กร ปัญหาที่น่าปวดหัวที่สุดสำหรับผู้บริหารมักไม่ใช่เรื่อง "ไม่มีข้อมูล" แต่เป็นเรื่อง "ข้อมูลมีเยอะเกินไปและตัวเลขไม่ตรงกัน"

## 1.1 ทำไมตัวเลขเดียวกันจึงมีหลายคำตอบ?
ลองจินตนาการถึงสถานการณ์การประชุมประจำเดือน:
* **ฝ่ายขาย (Sales)** รายงานยอดขายเดือนนี้ที่: **9.8 ล้านบาท**
* **ฝ่ายบัญชี (Accounting)** รายงานยอดขายเดือนนี้ที่: **9.2 ล้านบาท**
* **หน้าจอ Dashboard (ของ CEO)** แสดงยอดขายเดือนนี้ที่: **10.1 ล้านบาท**

หากมองผิวเผิน อาจดูเหมือนมีใครสักคนโกหกหรือทำงานผิดพลาด แต่ในความเป็นจริง **ทั้ง 3 ตัวเลขอาจจะ "ถูกต้อง" ทั้งหมด** ภายใต้นิยามที่แตกต่างกัน:
1. **นิยามของเวลา (Time Definition):** ฝ่ายขายบันทึกยอดทันทีที่ลูกค้า "เซ็นใบสั่งซื้อ (PO)" แต่ฝ่ายบัญชีบันทึกยอดเมื่อ "ส่งมอบสินค้าและออกใบแจ้งหนี้ (Invoice)" 
2. **นิยามของการยกเลิก (Returns & Cancellations):** หน้าจอ Dashboard อาจแสดงยอดขายรวม (Gross Sales) โดยยังไม่ได้หักลบยอดคืนสินค้า แต่ฝ่ายบัญชีแสดงยอดสุทธิ (Net Sales)
3. **นิยามของภาษี (Taxes & VAT):** ตัวเลขของฝ่ายขายอาจรวม VAT 7% ไปแล้ว เพื่อใช้คำนวณเป้าหมาย แต่ตัวเลขบัญชีต้องถอด VAT ออก
4. **อัตราแลกเปลี่ยน (Exchange Rates):** หากเป็นบริษัทส่งออก ฝ่ายขายอาจใช้อัตราแลกเปลี่ยน ณ วันที่ตกลงราคา แต่ฝ่ายบัญชีใช้อัตราแลกเปลี่ยน ณ วันที่เงินเข้าบัญชีจริงๆ

## 1.2 ผลกระทบของความขัดแย้งทางข้อมูล
เมื่อเกิดเหตุการณ์เช่นนี้ การประชุมผู้บริหารจะเปลี่ยนจากการ "วิเคราะห์กลยุทธ์" ไปเป็น "การทะเลาะกันว่าตัวเลขของใครถูก" (Data brawls) 
* สิ้นเปลืองเวลาผู้บริหารระดับสูง
* เกิดความไม่ไว้วางใจในระบบไอที (Loss of Trust)
* ตัดสินใจผิดพลาด เพราะอิงจากสมมติฐานที่ต่างกัน

## 1.3 บทบาทของคลังข้อมูล (Data Warehouse) ในฐานะผู้ไกล่เกลี่ย
Data Warehouse จึงถูกสร้างขึ้นมาเพื่อแก้ปัญหานี้โดยเฉพาะ มันไม่ได้มีหน้าที่แค่ "เก็บข้อมูลย้อนหลัง" แต่มันทำหน้าที่สร้าง **"ความจริงเวอร์ชันเดียว (Single Version of Truth)"** ให้กับองค์กร
* สถาปนิกข้อมูลจะต้องจับฝ่ายขายและฝ่ายบัญชีมานั่งคุยกัน เพื่อสร้าง **พจนานุกรมข้อมูล (Data Dictionary)** 
* กำหนดให้ชัดเจนว่า บน Dashboard ถ้าเขียนคำว่า "ยอดขาย" มันแปลว่า "ยอดขายสุทธิที่หักคืนสินค้าและถอด VAT ออกแล้ว อิงตามวันที่ออกใบแจ้งหนี้"
* เมื่อทุกคนในองค์กรดึงข้อมูลจาก Data Warehouse ทุกคนจะเห็นตัวเลข **9.2 ล้านบาท** ตรงกันทั้งหมด 

การสร้าง Data Warehouse จึงเป็นงานทาง "การบริหารจัดการคนและข้อตกลง" มากพอๆ กับงานทาง "วิศวกรรมคอมพิวเตอร์"
