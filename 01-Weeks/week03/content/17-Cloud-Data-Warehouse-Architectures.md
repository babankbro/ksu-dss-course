# 17. สถาปัตยกรรมของ Cloud Data Warehouse ระดับโลก

โลกของคลังข้อมูลได้ก้าวพ้นยุคที่ต้องซื้อฮาร์ดแวร์ตู้เซิร์ฟเวอร์ขนาดใหญ่ (เช่น Teradata หรือ Oracle Exadata) มาตั้งในบริษัท เข้าสู่ยุคของ **Cloud Data Warehouse** ที่ยืดหยุ่นกว่ามหาศาล โดยมีแกนนำอย่าง Snowflake, Google BigQuery และ Amazon Redshift

## 17.1 นวัตกรรมแยกประมวลผลออกจากพื้นที่เก็บข้อมูล (Separation of Compute and Storage)
นี่คือความลับทางสถาปัตยกรรมที่เปลี่ยนโลกของ Data Warehouse ไปตลอดกาล:
* **ยุคเก่า (Coupled):** CPU และ Harddisk อยู่ในเครื่องเดียวกัน ถ้าข้อมูลเยอะขึ้นแต่คิวรีน้อย เราก็ต้องซื้อฮาร์ดแวร์ตู้ใหม่ทั้งใบ เสียเงินฟรีๆ ให้กับส่วนที่ไม่ได้ใช้
* **ยุคคลาวด์ (Decoupled):**
  - **Storage Layer (ที่เก็บข้อมูล):** เก็บข้อมูลลงบนบริการเก็บไฟล์ราคาถูก (เช่น Amazon S3) ข้อมูลจะพองโตระดับ Petabyte ก็จ่ายค่าเก็บแค่หลักพันบาทต่อเดือน
  - **Compute Layer (พลังคำนวณ):** เป็นเซิร์ฟเวอร์ (Virtual Warehouses) ที่เช่ามาเพื่อใช้วิเคราะห์ข้อมูลโดยเฉพาะ 
* **ผลลัพธ์:** วันสิ้นเดือนที่ทีมบัญชีต้องปิดงบ ระบบจะระดม CPU จำนวน 128 คอร์ (Compute) มารุมอ่านไฟล์ (Storage) ทำให้คิวรีเสร็จใน 5 วินาที พอปิดงบเสร็จ เราก็ปิดสวิตช์ CPU จ่ายค่าเช่าแค่ 5 วินาทีนั้น นี่คือสิ่งที่เรียกว่าการขยายขนาดแบบยืดหยุ่น (Elastic Scalability)

## 17.2 สถาปัตยกรรมแบบ Columnar Storage (เก็บข้อมูลแนวตั้ง)
ฐานข้อมูล OLTP ทั่วไปเก็บข้อมูลแนวนอน (Row-based) เช่น 1 บรรทัดเก็บทั้ง รหัส, ชื่อ, วันที่, ยอดเงิน
* แต่ Cloud Data Warehouse บันทึกข้อมูลเป็น **แนวตั้ง (Columnar)** 
* **เหตุผล:** ผู้บริหารมักคิวรีคำสั่ง "ขอผลรวมยอดขายทั้งหมด" 
* ถ้าเก็บแบบ Row-based คอมพิวเตอร์ต้องอ่านข้อมูลชื่อและวันที่ (ที่ไม่เกี่ยว) ติดมาด้วย เสียเวลาโหลด
* พอเก็บแบบ Column-based คอมพิวเตอร์จะข้ามไปอ่านไฟล์แท่ง "ยอดเงิน" แท่งเดียวมารวมกันเลย ทำให้ทำงานเร็วกว่า OLTP ถึง 10-100 เท่าเมื่อวิเคราะห์ข้อมูลขนาดใหญ่

## 17.3 ผู้เล่นหลักและแนวคิดที่แตกต่าง
1. **Google BigQuery (Serverless แท้จริง):** 
   - สถาปัตยกรรมซ่อนทุกอย่างไว้ ผู้ใช้ไม่ต้องกำหนดว่าอยากได้ CPU กี่ตัว (Serverless) แค่พิมพ์ SQL ยิงเข้าไป Google จะระดมเซิร์ฟเวอร์หลายพันตัวมาช่วยกันรันหลังบ้านให้เสร็จในเสี้ยววินาที แล้วคิดเงินตามปริมาณข้อมูลที่อ่าน 
2. **Snowflake (Multi-cluster Shared Data):** 
   - สถาปัตยกรรมที่ให้เราเปิดเซิร์ฟเวอร์ (Compute Cluster) หลายๆ วงได้อิสระ เช่น วงแรกให้ทีม Data Science รันโมเดลดึงข้อมูลเต็มเหนี่ยว วงที่สองให้ผู้บริหารดูรายงาน ทั้ง 2 วงแย่งกันอ่านไฟล์ดิสก์ก้อนเดียวกันได้ โดยไม่แย่งความเร็ว (No Resource Contention) ทำให้รายงานผู้บริหารไม่มีวันค้าง
3. **Amazon Redshift (MPP Cluster):**
   - ยังคงมีความเป็นกลุ่มเซิร์ฟเวอร์แบบดั้งเดิม (Massively Parallel Processing) แต่จูนความเร็วฮาร์ดแวร์ได้ลึก เหมาะกับองค์กรที่อยู่ใน Ecosystem ของ AWS อยู่แล้ว
