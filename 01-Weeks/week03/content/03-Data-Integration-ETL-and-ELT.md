# 3. กระบวนการบูรณาการข้อมูล (ETL และ ELT)

ข้อมูลไม่ได้ลอยข้ามจากระบบ OLTP มาเข้า Data Warehouse ได้เอง มันต้องผ่านท่อส่งข้อมูล (Data Pipeline) ซึ่งกระบวนการนี้คือหัวใจสำคัญและใช้แรงงานมากที่สุดในการทำระบบ DSS (มักใช้เวลา 70-80% ของทั้งโครงการ)

## 3.1 กระบวนการ ETL (Extract - Transform - Load) แบบดั้งเดิม
ในยุคก่อนที่ Cloud จะเฟื่องฟู ฐานข้อมูลปลายทางมีราคาแพงและประมวลผลช้า สถาปนิกจึงใช้รูปแบบ ETL:

**1. E (Extract) - การสกัดข้อมูล**
* การดึงข้อมูลออกมาจากระบบต้นทาง เช่น ERP, CRM, ไฟล์ Excel หรือ API จากภายนอก
* **Full Extraction:** ดึงใหม่ทั้งหมดทุกวัน (เหมาะกับตารางเล็กๆ เช่น ตารางจังหวัด)
* **Incremental Extraction:** ดึงเฉพาะ "ของใหม่หรือของที่เพิ่งอัปเดต" ตั้งแต่เมื่อวาน (เหมาะกับตารางใหญ่ เช่น ตารางยอดขาย) มักใช้การดูจากฟิลด์ `last_updated_timestamp`

**2. T (Transform) - การแปลงสภาพข้อมูล**
* ข้อมูลดิบมักจะสกปรก จึงต้องนำมาพักไว้ที่เซิร์ฟเวอร์ตรงกลางเพื่อทำความสะอาด
* **Standardization:** แปลงให้เป็นมาตรฐาน (เช่น แปลงวันที่ `12/31/2023` เป็น `2023-12-31`)
* **Deduplication:** การลบข้อมูลซ้ำซ้อน (เช่น สมชายสมัครสมาชิก 2 ครั้ง ต้องรวมเป็นบัญชีเดียว)
* **Lookup & Enrichment:** การเอาข้อมูลไปเทียบหาค่าอื่น เช่น เอาพิกัด Latitude/Longitude ไปเทียบหาชื่อเขตและจังหวัด
* **Handling Missing Values:** การจัดการช่องว่าง อาจจะใส่คำว่า "Unknown" เพื่อไม่ให้โปรแกรมวิเคราะห์พัง

**3. L (Load) - การโหลดข้อมูลเข้าคลัง**
* การเอาข้อมูลที่สะอาดเอี่ยมแล้ว เทลงไปในตาราง Fact และ Dimension ใน Data Warehouse อย่างเป็นระเบียบ

## 3.2 การเปลี่ยนผ่านสู่ ELT (Extract - Load - Transform)
ปัจจุบัน เทคโนโลยี Cloud Data Warehouse (เช่น Google BigQuery, Snowflake) มีพลังการประมวลผล (Compute) มหาศาลและราคาถูกลงมาก ทำให้วงการย้ายมาใช้รูปแบบ ELT:

**1. E (Extract):** ดึงข้อมูลดิบออกมา
**2. L (Load):** เทข้อมูลดิบๆ สกปรกๆ ทั้งหมดลงไปใน Cloud Data Warehouse ก่อนเลยโดยไม่คิดมาก (เรียกว่าโซน Raw หรือ Bronze)
**3. T (Transform):** ใช้ขุมพลังของคลาวด์ รันคำสั่ง SQL ภายใน Warehouse นั้นเลย เพื่อปั้นข้อมูลดิบให้กลายเป็นข้อมูลที่สะอาด

**ข้อดีของ ELT:**
* **เก็บประวัติต้นฉบับ (Raw History):** หากวันหนึ่งเราค้นพบว่าตรรกะการทำความสะอาดข้อมูล (Transform) ของเราผิดพลาดมาตลอด 1 ปี เราสามารถกลับไปเขียน SQL แปลงข้อมูลใหม่จาก Raw Data ได้ทันที (ถ้าเป็น ETL แบบเก่า ข้อมูลดิบอาจถูกทิ้งไปแล้ว)
* **ยืดหยุ่น (Agility):** ทีม Data Engineer ทำงานง่ายขึ้น โฟกัสแค่การดูดข้อมูลมาแปะไว้ ส่วนทีม Data Analyst สามารถใช้ภาษา SQL ที่ถนัดในการปั้นข้อมูล (Transformation) ผ่านเครื่องมือสมัยใหม่อย่าง **dbt (data build tool)**
