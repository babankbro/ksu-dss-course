# สรุปและอธิบายสไลด์ Week 06: Data Mining II (CLUSTERING & ASSOCIATION RULES)
เอกสารนี้อธิบายความหมายและภาพรวมของสไลด์แต่ละหน้า โดยเน้นคำศัพท์ (Technical Terms) อธิบายกระบวนการ Unsupervised Learning และเชื่อมโยงอ้างอิงกับเอกสารเจาะลึกในโฟลเดอร์ `content/` พร้อมตอบคำถามที่สอดแทรกในสไลด์

---

## สไลด์ที่ 1-2: หน้าปกและ 10 คำถามเปลี่ยน Pattern เป็น Decision
**ภาพรวม:** สัปดาห์นี้เน้นที่ Unsupervised Learning คือการหา Pattern ที่ซ่อนอยู่ในข้อมูลโดยไม่มี "เฉลย" หรือ Target Variable ล่วงหน้า (ต่างจาก Classification ในสัปดาห์ 5) ได้แก่ Clustering (การจัดกลุ่ม) และ Association Rules (กฎความสัมพันธ์)
**คำศัพท์และคีย์เวิร์ดสำคัญ:**
*   **Pattern Discovery:** การค้นหารูปแบบในข้อมูล
*   **Decision Evidence:** การนำรูปแบบที่พบไปใช้เป็นหลักฐานประกอบการตัดสินใจ
**คำถามในสไลด์ (สไลด์ 2):**
1. หน่วยวิเคราะห์คืออะไร? **ตอบ:** ต้องกำหนดชัดเจนว่า 1 แถวแทนอะไร (เช่น 1 ลูกค้า, 1 บิล)
2. Feature กำหนดความคล้ายอย่างไร? **ตอบ:** ตัวแปรที่เราเลือกจะเป็นตัวนิยามว่าใครคล้ายใคร
3. Scale ใดกำลังครอบงำระยะทาง? **ตอบ:** ตัวแปรที่มีค่ามากอาจบดบังตัวแปรอื่น จึงต้อง Scaling
4. K-Means converged ไปจุดใด? **ตอบ:** การหยุดทำงานขึ้นอยู่กับ Seed และรูปทรงข้อมูล
5. k ใดทั้งดีและบริหารได้? **ตอบ:** จำนวนกลุ่มต้องดีทางสถิติและทีม Business ดูแลไหว
6. กลุ่มเสถียรข้าม seed/เวลาไหม? **ตอบ:** เป็นตัวบอกว่ากลุ่มมีอยู่จริงหรือแค่บังเอิญ
7. Algorithm ใดตรงรูปทรงข้อมูล? **ตอบ:** K-Means เน้นทรงกลม DBSCAN เน้นความหนาแน่นอิสระ
8. Support–Confidence–Lift บอกอะไร? **ตอบ:** บอกความบ่อย ความเชื่อมั่น และความเก่งของกฎ
9. Association เป็นเหตุและผลหรือไม่? **ตอบ:** ไม่ใช่! เป็นแค่ความเกี่ยวข้องกัน (Correlation)
10. จะทดลองและ monitor อย่างไร? **ตอบ:** ต้องทำ A/B Test และเฝ้าระวังพฤติกรรมเปลี่ยน (Drift)
**คำถามในสไลด์ (สไลด์ 1):**
*   ถ้า algorithm คืนมา 3 clusters องค์กรมีลูกค้า 3 ประเภทจริงหรือไม่? (จาก Notes)
**ตอบ:** ไม่จริงเสมอไป Algorithm แค่แบ่งกลุ่มทางคณิตศาสตร์ให้ตามสูตร แต่กลุ่มเหล่านั้นจะมีอยู่จริงในเชิงธุรกิจและพร้อมให้เราทำ Marketing Action หรือไม่ ต้องผ่านการตีความ (Profiling) และทดสอบก่อน *(อ้างอิง: [บทที่ 01] Discovery vs Decision)*

## สไลด์ที่ 3: 3 Clusters ไม่ได้แปลว่า 3 Customer Segments
**ภาพรวม:** 
*   **Algorithm Output:** สร้าง Cluster ออกมาเป็นตัวเลข (0, 1, 2) ซึ่งมาจากการคำนวณระยะทาง (Distance) ไม่มีชื่อ ไม่มีเจตนา
*   **Decision Segment:** คือกลุ่มคนที่มีพฤติกรรมหรือบริบทคล้ายกันในโลกจริง ต้องเสถียร มีชื่อเรียก มีคนที่รับผิดชอบ (Owner) และพร้อมให้ทดสอบ (Experiment)
**อธิบาย/อ้างอิง:** ห้ามนำผลจาก Algorithm ไปใช้งานทันทีโดยไม่ตีความ *(อ้างอิง: [บทที่ 01] Discovery vs Decision และ [บทที่ 05] Choosing K and Profiling)*

## สไลด์ที่ 4: Unsupervised Learning ไม่มีเฉลย จึงต้องใช้หลักฐาน 3 ชั้น
**ภาพรวม:** เนื่องจากไม่มีเฉลย (Labels) จึงต้องพิสูจน์ 3 ด่าน (Decision Gate)
1. **Technical:** วัดค่าความเกาะกลุ่ม (Cohesion), การแยกขาด (Separation)
2. **Domain:** สมเหตุสมผลในเชิงธุรกิจ (Semantics) มีหน้าตาที่มนุษย์อธิบายได้
3. **Decision:** มีทีมรับผิดชอบรองรับหรือไม่ (Capacity/KPI)
**อธิบาย/อ้างอิง:** *(อ้างอิง: [บทที่ 01] Discovery vs Decision)*

## สไลด์ที่ 5: สองเส้นทางค้นหา Pattern ใช้ Decision Gate เดียวกัน
**ภาพรวม:** เส้นทางค้นหา Pattern 2 แบบ
*   **Clustering (จัดกลุ่ม):** (Objects ➔ Features ➔ Distance ➔ Groups)
*   **Association Rules (กฎความสัมพันธ์):** (Transactions ➔ Itemsets ➔ Rules)
**คำถามในสไลด์:**
*   ใครคล้ายใคร? **ตอบ:** เป็นคำถามหลักของการทำ Clustering
*   อะไรเกิดร่วมกัน? **ตอบ:** เป็นคำถามหลักของการทำ Association Rules
**อธิบาย/อ้างอิง:** ทั้งสองเทคนิค สุดท้ายต้องถูกนำไปผ่าน Gate เดียวกันคือ Validate ➔ Experiment ➔ Monitor 

## สไลด์ที่ 6: Feature คือคำตอบล่วงหน้าว่า ‘ความคล้าย’ หมายถึงอะไร
**ภาพรวม:** ตัวอย่างการสร้าง Feature ด้วย **RFM** Model:
*   **R (Recency):** วันตั้งแต่ซื้อครั้งล่าสุด
*   **F (Frequency):** จำนวนครั้งที่ทำธุรกรรม
*   **M (Monetary):** ยอดเงินสุทธิ
**อธิบาย/อ้างอิง:** การกำหนด Feature ต้องนิยามชัดเจน เช่น Snapshot Date เดียวกัน, Observation Window ที่ชัดเจน หากเปลี่ยนการคำนวณ Feature ความหมายของ "ความคล้าย" ก็จะเปลี่ยนไปทันที *(อ้างอิง: [บทที่ 02] Feature Space and RFM)*

## สไลด์ที่ 7: Scaling เปลี่ยนระยะทาง — จึงเปลี่ยนเส้นแบ่ง Cluster
**ภาพรวม:** Algorithm ส่วนใหญ่ใช้วิธีวัดระยะทาง (Distance-based)
*   สมมติ ยอดเงิน (M) มีค่า 0–50,000 แต่ความถี่ (F) มีค่า 1–50
*   ถ้าไม่ปรับสเกล ตัวเลข 50,000 จะ "ครอบงำ (Dominate)" ระยะทางทั้งหมด ทำให้ Algorithm มองข้ามตัวแปรความถี่
**อธิบาย/อ้างอิง:** ต้องทำ Data Scaling เช่น StandardScaler หรือใช้ log1p สำหรับตัวแปรที่มีค่าเบ้ (Skewed) การ Scaling ถือเป็นการให้น้ำหนักเชิงนโยบายอย่างหนึ่ง *(อ้างอิง: [บทที่ 03] Scaling and Geometry)*

## สไลด์ที่ 8: K-Means วนซ้ำ: Initialize ➔ Assign ➔ Update
**ภาพรวม:** หลักการทำงานของ K-Means Algorithm
1. **Initialize:** สุ่มจุดศูนย์กลาง (Centroids) จำนวน k จุด
2. **Assign:** ให้ทุกจุดข้อมูล (Data point) วิ่งไปหา Centroid ที่ใกล้ตัวเองที่สุด
3. **Update:** คำนวณหาค่าเฉลี่ย (Mean) ของสมาชิกในกลุ่มใหม่ แล้วย้าย Centroid ไปตรงกลาง
4. **Stop?:** ถ้าย้ายน้อยมากหรือไม่ย้ายแล้ว ให้หยุด (Converged) ไม่งั้นวนกลับไปข้อ 2
**อธิบาย/อ้างอิง:** *(อ้างอิง: [บทที่ 04] K-Means Clustering)*

## สไลด์ที่ 9: Objective ลดระยะกำลังสองภายในกลุ่ม (Inertia/WCSS)
**ภาพรวม:** K-Means จะพยายามทำให้ระยะห่างจากจุดข้อมูลไปยังจุดศูนย์กลาง (Centroid) สั้นที่สุด เรียกว่า **Inertia** หรือ **WCSS** (Within-Cluster Sum of Squares) 
**อธิบาย/อ้างอิง:** 
*   จุดอ่อนของ K-Means คือพยายามแบ่งเส้นเป็นรูปทรงกลมรอบจุดศูนย์กลาง (Voronoi Cells) ถ้ากลุ่มข้อมูลจริงเป็นรูปทรงแปลกๆ (Elongated/Manifold) ขนาดต่างกันมาก หรือมี Outliers สูง K-Means จะแบ่งกลุ่มผิดพลาดได้ง่าย *(อ้างอิง: [บทที่ 04] K-Means Clustering)*

## สไลด์ที่ 10: Initialization ต่างกัน อาจ Converge คนละ Local Minimum
**ภาพรวม:** การสุ่มจุด Centroid ตอนเริ่มต้น (Random Seed) มีผลอย่างมาก 
*   Run A (Seed 7) อาจได้ผลลัพธ์แบบหนึ่ง, Run B (Seed 19) อาจได้ผลลัพธ์อีกแบบ
**อธิบาย/อ้างอิง:** ในทางปฏิบัติเราจึงมักใช้ `k-means++` ในการสุ่มจุดแรกให้กระจายตัวดีๆ และตั้งค่ารันซ้ำหลายๆ รอบ (Restarts) แล้วเลือกผลลัพธ์ที่ดีที่สุด *(อ้างอิง: [บทที่ 04] K-Means Clustering)*

## สไลด์ที่ 11: เลือก k ด้วยหลักฐานหลายมิติ ไม่ใช่เส้น Elbow เส้นเดียว
**ภาพรวม:** การหาจำนวนกลุ่ม (k) ที่เหมาะสม ไม่ควรดูแค่กราฟข้อศอก:
1. **Elbow:** ดูจังหวะที่ค่า Inertia เริ่มลดลงช้าๆ
2. **Silhouette:** วัดว่าจับกลุ่มแน่นแค่ไหนและห่างจากกลุ่มอื่นเท่าไร
3. **Stability:** กลุ่มเดิมยังเกิดซ้ำไหม ถ้าสุ่มตัวอย่างใหม่หรือเปลี่ยนเวลา
4. **Capacity:** ทีมการตลาดสามารถออกแคมเปญรองรับลูกค้าได้กี่กลุ่มในชีวิตจริง? (ถ้าแบ่ง 10 กลุ่มแต่ทีมดูแลไหวแค่ 3 กลุ่ม ก็ไม่ควรเลือก k=10)
**อธิบาย/อ้างอิง:** *(อ้างอิง: [บทที่ 05] Choosing K and Profiling และ [บทที่ 18] Evaluating Clustering Stability)*

## สไลด์ที่ 12: Silhouette อ่านทั้งค่าเฉลี่ยและรูปร่างราย Cluster
**ภาพรวม:** สูตร `s = (b - a) / max(a, b)`
*   `a`: ระยะเฉลี่ยระหว่างเพื่อนๆ ในกลุ่มเดียวกัน (ยิ่งน้อยยิ่งดี = เกาะกลุ่มแน่น)
*   `b`: ระยะเฉลี่ยไปยังกลุ่มเพื่อนบ้านที่ใกล้ที่สุด (ยิ่งมากยิ่งดี = ห่างไกลจากกลุ่มอื่น)
*   ค่าอยู่ระหว่าง -1 ถึง +1 (+1 คือกลุ่มแยกชัดเจน, 0 คือคาบเกี่ยว, -1 คืออยู่ผิดกลุ่ม)
**อธิบาย/อ้างอิง:** ห้ามดูแค่ค่า Silhouette เฉลี่ยรวม ต้องพล็อตกราฟดูรูปร่าง (Distribution) ของแต่ละกลุ่มด้วย ว่ามีกลุ่มเล็กๆ ที่ค่าติดลบซ่อนอยู่หรือไม่ *(อ้างอิง: [บทที่ 05] Choosing K and Profiling)*

## สไลด์ที่ 13: Profile ก่อนตั้งชื่อ — อธิบายพฤติกรรม ไม่ตีตราคน
**ภาพรวม:** ตัวอย่างการตีความ:
*   Cluster 0: เพิ่งซื้อ ซื้อถี่ มูลค่าปานกลาง ➔ แอคชั่น: ทดสอบความภักดี (Loyalty)
*   Cluster 1: หายไปนาน เคยซื้อถี่ มูลค่าสูง ➔ แอคชั่น: เสนอโปรโมชั่นดึงกลับ (Win-back)
**อธิบาย/อ้างอิง:** การตั้งชื่อ (Labeling) ควรใช้เพื่อสื่อสารพฤติกรรม ไม่ใช่การตัดสินหรือตีตรา (เช่น คนรวย/คนจน) และต้องตรวจสอบตัวอย่างหรือสัดส่วนข้อมูล (Median/IQR) ประกอบ *(อ้างอิง: [บทที่ 05] Choosing K and Profiling)*

## สไลด์ที่ 14: Stability Test (Seed ➔ Sample ➔ Time ➔ Action)
**ภาพรวม:** หลักฐานเรื่องความเสถียร (Stability) ต้องมีการทดสอบเสมอ
**คำถามในสไลด์:**
1. centroid/assignment ใกล้กัน? **ตอบ:** ทดสอบโดยรัน ≥10 ค่า Seed ถ้าเสถียรผลลัพธ์ต้องคล้ายเดิม
2. กลุ่มยังเกิดหรือไม่? **ตอบ:** ทดสอบโดยทำ bootstrap/subsample (สุ่มตัดข้อมูล) ว่ากลุ่มเดิมยังปรากฏไหม
3. profile/drift เปลี่ยนไหม? **ตอบ:** ทดสอบด้วย rolling snapshots เทียบเวลาที่เปลี่ยนไปว่าพฤติกรรมต่างจากเดิมหรือไม่
4. ยังคุ้มและทำได้ไหม? **ตอบ:** ประเมินผ่าน KPI/coverage ว่ากลุ่มนี้สร้างประโยชน์คุ้มค่าทำแคมเปญไหม
**อธิบาย/อ้างอิง:** *"ถ้ากลุ่มหายเมื่อเปลี่ยน seed หรือเดือน ➔ อย่ารีบ deploy"* เพราะแปลว่าเป็นแค่เหตุบังเอิญทางคณิตศาสตร์ *(อ้างอิง: [บทที่ 18] Evaluating Clustering Stability)*

## สไลด์ที่ 15: Hierarchical Clustering 
**ภาพรวม:** แตกต่างจาก K-Means ตรงที่ **ไม่ต้องกำหนด K ก่อน** แต่วิธีนี้จะเริ่มจากให้ทุกจุดเป็น 1 กลุ่ม แล้วค่อยๆ จับคู่กลุ่มที่อยู่ใกล้กันมารวมกันจากล่างขึ้นบนจนเหลือกลุ่มเดียว (Agglomerative)
*   สามารถสร้างโครงสร้างกราฟรูปต้นไม้ (Dendrogram) เพื่อให้ Analyst เลือกตัด (Cut) ได้ตามความเหมาะสม
*   วิธีการวัดระยะห่างระหว่างกลุ่ม (Linkage): Ward (เน้นลด variance), Complete, Average, Single
**อธิบาย/อ้างอิง:** *(อ้างอิง: [บทที่ 06] Hierarchical Clustering)*

## สไลด์ที่ 16: DBSCAN (Density-Based Clustering)
**ภาพรวม:** สร้างกลุ่มจาก "ความหนาแน่น" (Density) 
*   พารามิเตอร์หลัก: `eps` (รัศมี) และ `min_samples` (จำนวนสมาชิกขั้นต่ำที่รวมกันแล้วเรียกว่าหนาแน่น)
*   **จุดเด่น:** สามารถจับกลุ่มรูปร่างแปลกๆ หรือบิดเบี้ยว (Irregular shape) ได้อิสระ และคัดแยก Outlier (Noise) ออกไปโดยไม่เอามารวมในกลุ่ม
*   **ข้อจำกัด:** แพ้เรื่อง Scale หรือกลุ่มที่มีความหนาแน่นไม่เท่ากัน (Varying density)
**อธิบาย/อ้างอิง:** *(อ้างอิง: [บทที่ 07] DBSCAN Clustering)*

## สไลด์ที่ 17: Algorithm Fit: รูปทรง • Scale • Deployment
**ภาพรวม:** สรุปเปรียบเทียบจุดเด่นของอัลกอริทึม
*   **K-Means:** ทำงานเร็ว เหมาะกับข้อมูลสเกลใหญ่ (Big Data) แต่ต้องกำหนด K ทรงของกลุ่มมักเป็นวงกลม (Convex)
*   **Hierarchical:** เห็นโครงสร้างลึกซึ้ง เหมาะตอนยังไม่รู้จำนวนกลุ่ม ไม่เหมาะกับข้อมูลมหาศาล (ช้า)
*   **DBSCAN:** เก่งเรื่องการแยก Outlier ค้นหากลุ่มตามความหนาแน่น ไม่บังคับรูปร่าง
**อธิบาย/อ้างอิง:** "ไม่มี Algorithm ที่ดีที่สุด หากไม่ระบุเงื่อนไขข้อมูลทางเรขาคณิตและโจทย์ธุรกิจ" *(อ้างอิง: [บทที่ 08] Choosing Clustering Algorithms)*

## สไลด์ที่ 18: Association Rules (กฎความสัมพันธ์)

4. สร้างกฎ (Generate rules) และกรองทิ้ง (Prune)

## สไลด์ที่ 19-20: Support • Confidence • Lift
**ภาพรวม:** การประเมินกฎ A ➔ B (ถ้าซื้อ A แล้วจะซื้อ B)
*   **Support:** สัดส่วนของบิลที่มีทั้ง A และ B เมื่อเทียบกับบิลทั้งหมด (เกิดขึ้นบ่อยแค่ไหน)
*   **Confidence:** ถ้าซื้อ A ไปแล้ว โอกาสที่จะซื้อ B ต่อมีกี่เปอร์เซ็นต์ (P(B|A))
*   **Lift:** ความเก่งของกฎ เมื่อเทียบกับค่าเฉลี่ยปกติที่คนซื้อ B (Base Rate)
**คำถามในสไลด์:** *"Confidence สูงแต่ทำไมไม่ควรใช้ (Base-rate Trap)?"*
*   *ตอบ:* สไลด์ที่ 20 เตือนว่า แม้ Confidence ของกฎ A ➔ B จะสูงถึง 92% แต่ถ้าสินค้า B มี Base Rate (คนทั่วไปซื้ออยู่แล้ว) ถึง 90% แปลว่ากฎนี้ทำให้โอกาสซื้อเพิ่มขึ้นนิดเดียวเท่านั้น (Lift = 0.92 / 0.90 ≈ 1.02) กฎที่ Lift ใกล้เคียง 1 ถือว่าไร้ประโยชน์ เพราะแทบไม่ต่างจากการเดาตามความนิยมปกติ *(อ้างอิง: [บทที่ 09] Association Rules and Metrics)*

## สไลด์ที่ 21: Apriori vs FP-Growth
**ภาพรวม:** เปรียบเทียบ Algorithm หาความสัมพันธ์
*   **Apriori:** ทำงานแบบไล่สแกน สร้างคู่สินค้า (Candidates) ไปเรื่อยๆ โดยใช้หลักการตัดกิ่ง (Downward Closure) คือ ถ้า A, B คู่กันไม่บ่อย งั้น A, B, C ก็ย่อมไม่บ่อยด้วย ข้อเสียคือใช้เวลา Scan นาน ถ้ารายการเยอะมากจะรันไม่ขึ้น (Candidate explosion)
*   **FP-Growth:** แก้ปัญหาความอืดโดยบีบข้อมูลทั้งหมดลงบน Tree (FP-Tree) แค่รอบเดียว ไม่ต้องสุ่มสร้างคู่ประสม เหมาะกับบิ๊กดาต้า
**อธิบาย/อ้างอิง:** *(อ้างอิง: [บทที่ 10] Apriori and FP-Growth)*

## สไลด์ที่ 22: Association ≠ Causation (ต้องผ่าน Experiment Gate)
**ภาพรวม:** รูปแบบ (Rule) เป็นแค่ "ความเกี่ยวข้องกัน" ไม่ใช่ "ความเป็นเหตุเป็นผล"
*   แม้เจอความสัมพันธ์ (เช่น ซื้อผ้าอ้อมแล้วซื้อเบียร์) แต่ถ้าอยากแน่ใจว่ามัน Work ต้องทำ **A/B Test** เสมอ
*   ใช้กลุ่มควบคุม (Control Group) เทียบกับกลุ่มทดลอง (Treatment Group) เพื่อดูว่ามาร์จิ้นเพิ่มขึ้นจริงไหม พร้อมตั้ง Guardrails (ป้องกันผลเสีย เช่น ของขาดสต็อก หรือลูกค้าด่า)
