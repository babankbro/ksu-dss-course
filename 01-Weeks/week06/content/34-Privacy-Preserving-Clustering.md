# 34. การจัดกลุ่มบนข้อมูลส่วนบุคคล (Privacy-Preserving Clustering)

ในบทที่ 35 ของสัปดาห์ 5 เราพูดถึง Federated Learning ในการทำ Classification ไปแล้ว 
แต่คำถามคือ **ถ้าเป็น Unsupervised Learning (เช่น K-Means) เราจะทำ Federated Learning ได้หรือไม่?** 

สมมติโรงพยาบาล 5 แห่ง อยากรวมฐานข้อมูลผู้ป่วยมะเร็ง 1 แสนคน เพื่อรัน K-Means หา "กลุ่มอาการโรครูปแบบใหม่" แต่กฎหมาย PDPA ห้ามเด็ดขาดไม่ให้โรงพยาบาลส่งรายชื่อและประวัติผู้ป่วยมารวมกันที่ส่วนกลาง

## 34.1 Federated K-Means (K-Means ไร้รอยต่อข้ามเซิร์ฟเวอร์)
นักวิจัยคอมพิวเตอร์แก้ปัญหานี้ด้วยวิธีที่ฉลาดมาก:
1. **Server กลาง:** สุ่มพิกัด Centroid (จุดศูนย์กลาง) 3 จุด ลอยๆ ขึ้นมา แล้วส่งพิกัด 3 จุดนี้ ไปให้เซิร์ฟเวอร์ของโรงพยาบาลทั้ง 5 แห่ง
2. **Local K-Means:** โรงพยาบาลแต่ละแห่ง จะเอา Centroid 3 จุดนั้น ไปกวาดต้อนผู้ป่วย "ภายในตึกตัวเอง" (ไม่มีข้อมูลไหลออกนอกตึก)
3. **การส่งกลับ (Aggregating):** โรงพยาบาลแต่ละแห่ง **จะไม่ส่งรายชื่อคนไข้กลับมา** แต่จะส่งแค่ "คณิตศาสตร์ค่าเฉลี่ยใหม่ (Local New Centroids)" และ "จำนวนคนในกลุ่มนั้น" กลับมาให้ Server กลาง
4. **Server กลางผสมข้อมูล:** นำพิกัดค่าเฉลี่ยใหม่จาก 5 โรงพยาบาล มาหา "ค่าเฉลี่ยถ่วงน้ำหนัก (Weighted Average)" (พิกัดไหนคนไข้เยอะ พิกัดนั้นมีน้ำหนักมาก) เกิดเป็น **Global Centroids (เวอร์ชันอัปเกรด)**
5. **ทำซ้ำลูป:** ส่ง Global Centroids กลับไปให้ 5 โรงพยาบาลรันใหม่ (ทำข้อ 2-4 วนไปจนกว่าจุดจะหยุดนิ่ง)

## 34.2 Differential Privacy (การใส่คลื่นรบกวน)
เพื่อป้องกันไม่ให้แฮกเกอร์แอบแงะดูพิกัด Global Centroids แล้วดักทางกลับไปหาประวัติผู้ป่วยได้ 
ในจังหวะที่โรงพยาบาลส่งพิกัดค่าเฉลี่ยกลับมาที่ส่วนกลาง ระบบจะใส่ **"Differential Privacy (สุ่มบวกค่าตัวเลขหลอกๆ เข้าไปนิดหน่อย)"** ทำให้แฮกเกอร์เดาทางย้อนกลับไม่ได้ 100% แต่พิกัดโดยรวมยังคงความแม่นยำเพียงพอที่จะทำให้ K-Means ลู่เข้าหากลุ่มอาการโรคที่แท้จริงได้
