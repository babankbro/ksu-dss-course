# 29. การจัดกลุ่มข้อมูลไหลบ่า (Streaming Data Clustering)

K-Means และ DBSCAN ดั้งเดิม ถูกออกแบบมาบนสมมติฐานว่า "ข้อมูลทุกอย่างนอนนิ่งๆ อยู่ใน Harddisk (Batch Processing)" 
แต่โลกความจริง ข้อมูลอย่างทราฟฟิกเว็บ พิกัด GPS หรือข้อมูลจากเซนเซอร์ IoT เป็น **"สายน้ำที่ไหลบ่าตลอดเวลา (Streaming Data)"** ถ้าเรามัวแต่เอาน้ำไปเก็บใส่โอ่ง (Database) แล้วค่อยรัน K-Means พรุ่งนี้เช้า... มันช้าไปแล้ว!

## 29.1 ข้อจำกัดทางฮาร์ดแวร์
การจะรัน K-Means ใหม่ทุกวินาทีที่มีข้อมูลใหม่เข้ามา จะทำให้ CPU และ RAM ระเบิด
เราต้องการอัลกอริทึมที่ **"ดูข้อมูลแค่รอบเดียว แล้วจำเฉพาะแก่นสารทิ้งข้อมูลดิบไปเลย (Single-pass Algorithm)"**

## 29.2 อัลกอริทึมมหาชน: BIRCH
(Balanced Iterative Reducing and Clustering using Hierarchies)
* **การทำงาน:** เมื่อข้อมูลจุดใหม่ไหลเข้ามา BIRCH จะไม่เก็บค่า X,Y ของจุดนั้นไว้ แต่มันจะวาด "วงกลมเล็กๆ (Clustering Feature)" คลุมจุดนั้นไว้
* พอจุดที่ 2 ไหลเข้ามา ถ้าใกล้กัน มันจะขยายวงกลมให้กว้างขึ้น พร้อมกับเก็บแค่ค่า 3 อย่าง:
  1. จำนวนคนในวงกลมนี้ (N)
  2. ผลรวมของค่าพิกัด (Linear Sum)
  3. ผลรวมของกำลังสอง (Squared Sum)
* ด้วยค่า 3 อย่างนี้ BIRCH สามารถหา "จุดศูนย์กลาง" และ "รัศมี" ของวงกลมได้อย่างแม่นยำ โดยไม่ต้องจำหน้าลูกค้าเลย! 
* เมื่อวงกลมเล็กๆ (Micro-clusters) ถูกวาดเต็มจอ คอมพิวเตอร์ก็จะรัน K-Means เบาๆ เพื่อจับวงกลมพวกนั้นมารวมกันเป็นกลุ่มใหญ่อีกที 

## 29.3 การประยุกต์ใช้งาน (Real-time DSS)
* ตรวจจับการโจมตีเว็บ (DDoS): ถ้ามี IP แปลกๆ หลุดเข้ามาแล้วถูก BIRCH โยนเข้า "คลัสเตอร์กลุ่มเสี่ยง" ระบบ Firewall จะดีด IP นั้นทิ้งแบบวินาทีต่อวินาที
* การจัดกลุ่ม Trending: วิเคราะห์ว่า Hashtag ใน Twitter ตอนนี้กำลังเกาะกลุ่มพูดถึงเรื่องอะไรอยู่ (แบบ Real-time)
