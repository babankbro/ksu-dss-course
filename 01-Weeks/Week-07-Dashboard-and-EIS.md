# 📘 สัปดาห์ที่ 7 — การออกแบบแผงควบคุมข้อมูลและระบบสารสนเทศสำหรับผู้บริหาร

⬅️ [[Week-06-Data-Mining-II]] | ➡️ [[Week-08-Midterm-Exam]]

## 🎯 จุดประสงค์การเรียนรู้
1. อธิบายบทบาทของ [[Executive-Information-Systems|EIS]] และหลักการลดภาระทางปัญญา (Cognitive load) ของผู้ใช้
2. เลือกประเภทกราฟให้เหมาะกับโครงสร้างข้อมูลและคำถามที่ต้องการตอบ
3. ออกแบบแผงควบคุมที่สื่อสาร **บริบทของข้อมูล** ได้ชัดเจน ไม่คลุมเครือ
4. อธิบายบทบาทของ Metadata, Data Lineage และ Semantic Layer ต่อความน่าเชื่อถือของระบบ

## 📖 เนื้อหาบรรยาย (2 ชม.)

### ช่วงที่ 1 (30 นาที) — EIS และภาระทางปัญญา
→ [[Executive-Information-Systems]]
- ผู้บริหารมีเวลาจำกัดและต้องตัดสินใจภายใต้ข้อมูลจำนวนมาก → ระบบต้องลด **Cognitive load**
- แผงควบคุมที่ดีไม่ใช่กราฟิกสวยงาม แต่คือการสื่อสาร **บริบทของข้อมูล (Contextual Awareness)** อย่างชัดเจน ปราศจากความคลุมเครือ เพื่อนำไปสู่การกระทำที่รวดเร็ว
- ระดับของ dashboard: Strategic (ผู้บริหาร) / Tactical (ผู้จัดการ) / Operational (หน้างาน) — ต่างกันที่ความถี่การรีเฟรชและระดับรายละเอียด

### ช่วงที่ 2 (35 นาที) — หลักการทัศนวิเคราะห์ (Visual Analytics)
→ [[Visual-Analytics]] · [[Dashboard-Design]]
- การเข้ารหัสข้อมูลด้วยการมองเห็น (visual encoding) และลำดับความแม่นยำในการรับรู้: ตำแหน่ง > ความยาว > มุม > พื้นที่ > สี
- การจับคู่คำถาม → ประเภทกราฟ:

| คำถาม | กราฟที่เหมาะ | ที่ควรเลี่ยง |
|---|---|---|
| เปรียบเทียบระหว่างหมวด | Bar chart | Pie chart เมื่อมีมากกว่า 5 หมวด |
| แนวโน้มตามเวลา | Line chart | Bar chart ที่มีหลายสิบแท่ง |
| การกระจายตัว | Histogram, Box plot | ค่าเฉลี่ยเดี่ยวๆ |
| ความสัมพันธ์ 2 ตัวแปร | Scatter plot | ตารางตัวเลขล้วน |
| สัดส่วนของทั้งหมด | Stacked bar, Treemap | Pie ซ้อน Pie |
| ความหนาแน่นเชิงพื้นที่ | Heatmap, Choropleth | 3D chart ทุกชนิด |

- จิตวิทยาการรับรู้สีและรูปร่าง: การใช้สีเชิงความหมาย, ความเข้าถึงได้สำหรับผู้มีภาวะตาบอดสี, data-ink ratio
- หลักการ UX/UI: ลำดับการอ่าน (Z-pattern), การจัดกลุ่ม, การใช้ค่าอ้างอิงเปรียบเทียบ (เป้าหมาย, ช่วงเดียวกันปีก่อน)

### ช่วงที่ 3 (35 นาที) — สถาปัตยกรรมหลังบ้านที่ทำให้ Dashboard น่าเชื่อถือ
→ [[Metadata-Lineage-Semantic-Layer]]

> [!warning] ปัญหาที่ทำลายความน่าเชื่อถือ
> หากตัวเลขรายได้บนแผงควบคุมไม่ระบุชัดว่าเป็นรายได้ก่อนหรือหลังหักค่าใช้จ่าย หรือไม่สามารถตรวจสอบได้ว่าตัวชี้วัดถูกดึงมาจากระบบใด ผู้บริหารย่อมเกิดความคลางแคลงใจ — และเมื่อสูญเสียความเชื่อมั่นแล้ว ระบบจะถูกเลิกใช้ ไม่ว่าตัวเลขจะถูกต้องเพียงใด

องค์ประกอบ 3 ชั้นที่จำเป็น:
1. **Metadata (อภิข้อมูล)** — ข้อมูลที่อธิบายโครงสร้างและที่มาของข้อมูลหลัก เพิ่มความสามารถในการทำ Data Governance
2. **Data Lineage (สายเลือดข้อมูล)** — ตรวจสอบย้อนกลับได้ว่าค่าสถิติบนแผงควบคุมเดินทางผ่านการแปลงรูปใดบ้าง และถูกใช้ในโมเดลใด
3. **Semantic Layer (ชั้นความหมาย)** — ตัวกลางที่แปลโครงสร้างฐานข้อมูลเชิงเทคนิคเป็นคำศัพท์ทางธุรกิจที่ทุกคนเข้าใจตรงกัน ลดปัญหา **Metric sprawl** (ตัวชี้วัดชื่อเดียวกันแต่คำนวณต่างกันในแต่ละแผนก) และสร้าง **Single Source of Truth**

- ทบทวนเส้นทาง: ETL → Warehouse → OLAP → Mining → Dashboard เป็นวงจรของ "descriptive analytics" ครบวง

## 🏭 กรณีศึกษา
**เมืองอัจฉริยะ (Smart City)** — ผู้ว่าราชการใช้แผงควบคุมเรียลไทม์ที่บูรณาการข้อมูลจากเซ็นเซอร์ IoT ทั่วเมือง แสดงจุดจราจรติดขัดด้วย heatmap พร้อม drill-ability ที่คลิกดูคุณภาพอากาศบริเวณนั้นได้ และมีปุ่มอนุญาตให้ AI ปรับรอบสัญญาณไฟจราจรได้ทันทีจากหน้าจอเดียว
**คำถามอภิปราย:** ปุ่มสั่งการบนแผงควบคุมนี้ทำให้ระบบข้ามเส้นจาก "สนับสนุนการตัดสินใจ" ไปสู่ "ตัดสินใจแทน" หรือไม่? ควรมีกลไกป้องกันอะไรบ้าง? (เชื่อมสู่ [[Explainable-AI-and-Governance]])
