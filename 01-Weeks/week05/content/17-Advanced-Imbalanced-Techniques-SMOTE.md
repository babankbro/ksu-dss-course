# 17. เทคนิคขั้นสูงสำหรับการจำลองคนกลุ่มน้อย (SMOTE และผองเพื่อน)

จากบทที่ 7 เรารู้ว่าถ้าคลาสโจร (Fraud) มีน้อยเกินไป โมเดลจะไม่ยอมเรียนรู้ วิธีหนึ่งที่นิยมคือการ Over-sampling (การปั๊มจำนวนโจรให้เยอะขึ้น) แต่ถ้าเราใช้วิธี **"ก๊อปปี้บรรทัดเดิมซ้ำๆ (Random Over-sampling)"** โมเดลก็จะเกิดการจำข้อสอบ (Overfit) จำหน้าโจรคนเดิมได้ขึ้นใจ

นี่คือจุดกำเนิดของเทคนิคการเสก "โจรโคลนนิ่ง (Synthetic Data)"

## 17.1 SMOTE (Synthetic Minority Over-sampling Technique)
SMOTE ไม่ได้ก๊อปปี้บรรทัดเดิม แต่มัน **"สร้างคนใหม่ที่ไม่เคยมีตัวตนอยู่จริงขึ้นมา"**
* **การทำงาน:**
  1. ไปหาโจรนาย A
  2. ไปหาโจรนาย B (ซึ่งเป็นเพื่อนบ้านที่อยู่ใกล้ที่สุดในอวกาศข้อมูล)
  3. ลากเส้นตรงเชื่อมระหว่างนาย A กับนาย B
  4. สุ่มสร้างโจรนาย C ขึ้นมา (เป็นจุดที่ลอยอยู่กลางเส้นตรงระหว่าง A กับ B)
* **ผลลัพธ์:** เราจะได้ฐานข้อมูลที่มีโจรเยอะขึ้น สู้กับกลุ่มคนปกติได้สูสี และโมเดลไม่เกิดการท่องจำเพราะนาย C เป็นจุดข้อมูลใหม่ที่มีลักษณะกระจายตัว (Generalization) ได้ดีกว่าการก๊อปปี้

## 17.2 ADASYN (Adaptive Synthetic Sampling)
* อัปเกรดความฉลาดมาจาก SMOTE อีกที
* แทนที่จะสุ่มโคลนนิ่งโจรทุกที่เท่าๆ กัน ADASYN จะเน้นไปสร้างโจรโคลนนิ่ง **"เฉพาะในดงที่โจรโดนคนปกติล้อมหน้าล้อมหลัง (Borderline)"**
* บริเวณที่โจรแยกตัวอยู่เดี่ยวๆ ชัดเจนอยู่แล้ว มันจะไม่ไปโคลนนิ่งเพิ่ม 
* ทำให้เส้นแบ่งเขตแดนระหว่างคลาสถูกผลักให้คมชัดมากขึ้นในจุดที่มีความสับสนสูง

## 17.3 ข้อควรระวังขั้นวิกฤต (The Leakage Warning)
ย้ำอีกครั้งในฐานะสถาปนิกข้อมูล:
คุณต้องแบ่งชุดสอบ (Test Set) เก็บใส่ตู้เซฟล็อกกุญแจไว้ก่อน แล้วเอาเฉพาะชุด Train มาทำ SMOTE!
* ถ้านำข้อมูลทั้งหมดมาทำ SMOTE โจรโคลนนิ่งที่เกิดจากกรรมพันธุ์ของนาย A จะหลุดเข้าไปอยู่ในชุด Test
* พอโมเดลทำสอบ มันจะจำร่องรอยกรรมพันธุ์ได้และทายถูกหมด ทำให้ผู้บริหารหลงคิดว่าโมเดลพร้อม Go-Live แล้ว
* ดังนั้นในท่อ Data Pipeline จริงๆ ขั้นตอน SMOTE จะต้องบรรจุอยู่ **ข้างใน (Inside)** กระบวนการ Cross-Validation เท่านั้น ห้ามทำข้างนอกเด็ดขาด
