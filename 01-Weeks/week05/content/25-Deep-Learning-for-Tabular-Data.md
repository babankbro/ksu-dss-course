# 25. การประยุกต์ใช้ Deep Learning กับข้อมูลแบบตาราง (Tabular Data)

แม้ว่า Deep Learning (โครงข่ายประสาทเทียม) จะเป็นราชาในวงการประมวลผลภาพ (Computer Vision) และข้อความ (NLP) แต่สำหรับข้อมูล "แบบตาราง (Tabular Data)" ที่มีคอลัมน์อายุ, เงินเดือน, ยอดหนี้ นั้น โมเดลตระกูลต้นไม้ (Gradient Boosting อย่าง XGBoost) ยังคงเป็นแชมป์เปี้ยนมายาวนาน

ทำไม Deep Learning ถึงเอาชนะตารางข้อมูลไม่ได้ง่ายๆ? และนวัตกรรมใหม่ๆ กำลังพยายามแก้ปัญหานี้อย่างไร?

## 25.1 ทำไม Neural Networks ถึงแพ้ Decision Trees บนตาราง?
1. **Lack of Locality (ขาดความต่อเนื่อง):** ในรูปภาพ พิกเซลที่อยู่ติดกันมักมีความหมายเชื่อมโยงกัน แต่ในตาราง คอลัมน์ที่ 1 (อายุ) กับคอลัมน์ที่ 2 (รหัสไปรษณีย์) อาจไม่มีความเกี่ยวข้องกันเลย โครงข่ายประสาทเทียมที่เก่งเรื่องการหาความต่อเนื่องจึงสับสน
2. **Uninformative Features (คอลัมน์ขยะ):** ต้นไม้ตัดสินใจสามารถ "เพิกเฉย" ต่อคอลัมน์ที่ไม่มีประโยชน์ได้อย่างเด็ดขาด (โดยการไม่เลือกมันมาตัดกิ่ง) แต่ Neural Network มักพยายามให้ค่าน้ำหนัก (Weights) แก่ทุกคอลัมน์ ทำให้ข้อมูลขยะเข้ามารบกวน
3. **Scale Sensitivity:** Neural Network ต้องการให้ข้อมูลทุกคอลัมน์ถูกบีบ (Scale) ให้อยู่ในช่วง 0-1 เสมอ ในขณะที่ต้นไม้ไม่สนใจสเกลเลย

## 25.2 นวัตกรรม TabNet
**TabNet (สร้างโดย Google Research)** คือสถาปัตยกรรม Deep Learning ที่ถูกออกแบบมาเพื่อทำลายข้อจำกัดด้านบนโดยเฉพาะ:
* **กลไก Sequential Attention:** มันเลียนแบบการทำงานของ Decision Tree โดยในแต่ละรอบการคำนวณ มันจะสร้าง "หน้ากาก (Mask)" เพื่อบังคอลัมน์ขยะทิ้งไป และบังคับให้โมเดลโฟกัสเฉพาะคอลัมน์ที่สำคัญ (Sparse Feature Selection)
* **ผลลัพธ์:** TabNet สามารถทำคะแนนสูสีหรือชนะ XGBoost ได้ในหลายชุดข้อมูล และที่สำคัญคือ มันสามารถ "อธิบายตัวเองได้ (Interpretable)" ว่ามันเลือกตัดสินใจจากคอลัมน์ไหน (คล้ายกับการทำ Feature Importance ของต้นไม้)

## 25.3 Entity Embeddings สำหรับหมวดหมู่ (Categorical Variables)
ความลับอีกอย่างที่ทำให้ Deep Learning บนตารางเริ่มเป็นที่นิยม คือ **Entity Embeddings**
* ปกติรหัสไปรษณีย์ (Zip Code) มีหลายพันรหัส ถ้าใช้ One-hot Encoding ตารางจะบวมจนโมเดลพัง
* Deep Learning สามารถแปลงรหัสไปรษณีย์ ให้กลายเป็น "เวกเตอร์ความหมาย 3 มิติ (Dense Vector)" ได้
* ผลคือ โมเดลจะเรียนรู้เองว่า รหัสไปรษณีย์ "10110 (คลองเตย)" มีลักษณะความเสี่ยงใกล้เคียงกับ "10330 (ปทุมวัน)" และจับมันมาอยู่ใกล้กันในอวกาศคณิตศาสตร์ ซึ่งต้นไม้ทั่วไปทำแบบนี้ไม่ได้

**บทสรุป:** ในการสร้างระบบ DSS ยุคใหม่ องค์กรมักใช้ XGBoost เป็นฐานหลัก แต่เริ่มมีการนำ TabNet หรือ Entity Embeddings เข้ามาผสมผสานในท่อส่งข้อมูล (Pipeline) เพื่อดึงประสิทธิภาพสูงสุด
