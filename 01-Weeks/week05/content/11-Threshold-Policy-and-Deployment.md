# 11. นโยบายจุดตัด (Threshold is Policy) และการนำไปใช้งานจริง (Deployment)

โมเดล Classification ส่วนใหญ่ไม่ได้ตอบคำถามฟันธงว่า "เป็นโจร" หรือ "ไม่เป็นโจร" แต่โมเดลจะพ่นค่า **Score (ความน่าจะเป็น 0 ถึง 1)** ออกมา เช่น นาย A ได้สกอร์ 0.85 นาย B ได้สกอร์ 0.20

คำถามคือ "แล้วสกอร์เท่าไรถึงจะแปลว่า ทุจริต?" นี่ไม่ใช่การตัดสินใจทางคณิตศาสตร์ แต่เป็นการตัดสินใจทางนโยบายธุรกิจ (Business Policy)

## 11.1 การปรับจุดตัด (Threshold Tuning)
ค่าเริ่มต้นของซอฟต์แวร์ AI มักจะตั้ง Threshold = 0.5 (ถ้าสกอร์ > 0.5 ให้ฟันธงว่าใช่) 
**แต่คุณสามารถ (และควร) เลื่อนเส้นนี้ได้:**

* **เลื่อนเส้นตัดต่ำลง (เช่น > 0.2 จับหมด):** 
  - ผลลัพธ์: โมเดลจะหูไวตาไวมาก (Recall เพิ่มขึ้นพรวดพราด จับโจรได้เกือบหมด) 
  - ผลข้างเคียง: แจ้งเตือนมั่วซั่ว (False Positive บานเบอะ Precision ร่วงหล่น)
* **เลื่อนเส้นตัดสูงขึ้น (เช่น > 0.9 ค่อยจับ):** 
  - ผลลัพธ์: โมเดลจะมั่นใจชัวร์ๆ ค่อยเตือน (Precision สูงปรี๊ด ไม่จับคนบริสุทธิ์เลย) 
  - ผลข้างเคียง: โจรที่สกอร์ 0.89 จะลอยนวลหลุดไปได้ (Recall ตกฮวบ)

## 11.2 ศาสตร์แห่งการจัดกำลังคน (Capacity-based Threshold)
Threshold ที่ดีที่สุด ไม่ได้มาจากกราฟ ROC Curve แต่มาจาก "กำลังพลของแผนกคุณ"
* **ตัวอย่าง:** โมเดลจับทุจริตพ่นรายชื่อผู้ต้องสงสัยออกมา หากตั้ง Threshold = 0.5 จะมีใบแจ้งเตือน (Alerts) วันละ 10,000 ใบ
* แต่ทีมงานพนักงานตรวจสอบของคุณ มีกันแค่ 10 คน ตรวจได้เก่งสุดวันละ 500 เคส!
* **ทางแก้:** คุณต้องเลื่อน Threshold ขึ้นไปที่ 0.85 (หรือค่าใดๆ ก็ตาม) ที่บีบให้โมเดลพ่นรายชื่อออกมาแค่วันละ 500 เคสตัวท็อปๆ เพื่อให้แมตช์กับ Capacity ของทีมงานพอดี นี่คือการทำ Data Mining ที่อิงกับความเป็นจริง

## 11.3 เส้นทางสู่ Production (Deployment)
เมื่อได้โมเดลและ Threshold ที่ดีแล้ว การเอาระบบขึ้นใช้งานจริง (Go-live) จะต้องเช็คความพร้อม:
1. **Latency (ความหน่วง):** การดึงข้อมูลดิบมาผ่าน Data Prep และโยนเข้า Model จนได้ผลลัพธ์ ทำเสร็จภายในกี่มิลลิวินาที?
2. **Fallback Plan (แผนสำรอง):** ถ้าวันนี้เซิร์ฟเวอร์ Data Warehouse ล่ม โลจิกหลังปุ่มอนุมัติสินเชื่อจะทำอย่างไร? ปฏิเสธทุกคน? หรือใช้วิธีโยนให้มนุษย์รีวิวแทน?
3. **Evidence Record (การเก็บหลักฐาน):** เมื่อโมเดลตัดสินใจปฏิเสธลูกค้า ระบบจะต้อง "บันทึกข้อมูลทุกฟีเจอร์ ณ วินาทีนั้น" ลงใน Database เสมอ เพื่อเป็นหลักฐานให้ตรวจสอบย้อนหลังได้ (Audit Trail)
4. **Monitoring (การเฝ้าระวังหลังเปิดตัว):** 
   - โมเดล AI มีลักษณะเหมือน "ผลไม้สด" วันที่มันออกมาจากห้องแล็บ มันฉลาดที่สุด แต่มันจะค่อยๆ เน่าเสียและโง่ลง (Model Drift / Concept Drift) เมื่อพฤติกรรมมนุษย์เปลี่ยนไป 
   - ระบบ DSS ที่ดีต้องมี Dashboard ไว้คอยมอนิเตอร์ว่า "เดือนนี้โมเดลเราเริ่มทายแม่นน้อยลงหรือยัง?" และตั้งรอบเวลาการรีเทรน (Retrain) ใหม่ทุกๆ 3 หรือ 6 เดือน
