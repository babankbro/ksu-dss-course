# 22. MLOps: การเฝ้าระวังโมเดล (Model Monitoring) และภาวะการเลื่อนลอย (Drift)

ในอดีต Data Scientist สร้างโมเดลเสร็จแล้วก็ส่งไฟล์ข้ามกำแพงไปให้ฝั่ง IT ฝังลงเว็บ แล้วก็ลืมมันไปเลย หารู้ไม่ว่า "โมเดลซอฟต์แวร์เสื่อมสภาพเร็วกว่าฮาร์ดแวร์" ศาสตร์แห่ง **MLOps (Machine Learning Operations)** จึงถือกำเนิดขึ้น เพื่อจัดการวัฏจักรชีวิตของโมเดลหลังขึ้นโปรดักชัน

## 22.1 ทำไมโมเดล AI ถึงโง่ลง (Degradation)?
โมเดล Machine Learning เรียนรู้ตรรกะจากภาพสะท้อนอดีต ทันทีที่โลกแห่งความเป็นจริงเปลี่ยนไป โมเดลจะกลายเป็นไดโนเสาร์หลงยุค ปรากฏการณ์นี้เรียกว่า **Drift (การเลื่อนลอย)**

**1. Data Drift (พฤติกรรมข้อมูลเปลี่ยน):**
* โมเดลถูกฝึกมาด้วยข้อมูลลูกค้าวัย 30-40 ปี แต่ปีต่อมา บริษัทอัดโปรโมชั่นวัยรุ่น ทำให้มีเด็กอายุ 18 ทะลักเข้ามาสมัคร
* โลกความจริงผลลัพธ์ยังเหมือนเดิม แต่หน้าตาข้อมูลเปลี่ยนไป (Inputs change) โมเดลจะไม่เคยเห็นคนอายุ 18 มาก่อน ทำให้มันทายแบบสุ่มสี่สุ่มห้า

**2. Concept Drift (สัจธรรมเปลี่ยน):**
* ร้ายแรงกว่าข้อแรก! ตัวแปรเข้าเหมือนเดิมทุกอย่าง แต่ "ตรรกะความเป็นจริง" เปลี่ยนไป
* เช่น ก่อนวิกฤตโควิด: คนที่ทำงานสายการบิน (อาชีพ) + เงินเดือนสูง (รายได้) = กลุ่มลูกค้าชั้นดีสุดๆ อนุมัติผ่าน 100%
* ช่วงวิกฤตโควิด: คนที่ทำงานสายการบิน = คนที่มีความเสี่ยงตกงานสูงที่สุด! (ตรรกะพลิกกลับด้าน)
* ถ้าไม่มีใครปิดโมเดลนี้ มันจะยังคงแจกสินเชื่อให้พนักงานสายการบินต่อไปจนบริษัทล้มละลาย

## 22.2 หน้าปัดเฝ้าระวัง (Model Observability Dashboard)
ทีม MLOps จะไม่รอให้ตัวเลขขาดทุนวิ่งเข้าสมุดบัญชี แต่พวกเขาจะตั้ง Dashboard มอนิเตอร์โมเดลแบบ Real-time:
1. **Population Stability Index (PSI):** ตัวชี้วัดว่า กราฟอายุลูกค้าที่ไหลเข้ามาวันนี้ กับกราฟอายุลูกค้าตอนที่ใช้ฝึกสอน (Train) มันบิดเบี้ยวหน้าตาไม่เหมือนเดิมหรือยัง?
2. **Prediction Drift:** วันนี้โมเดลสั่งอนุมัติ 90% ทั้งที่ปกติมันอนุมัติแค่ 60% หรือไม่? 
3. **Ground Truth Delay:** ปัญหาคือ กว่าเราจะรู้ว่าลูกค้าเบี้ยวหนี้ (Concept Drift) ต้องรอ 3 เดือน! MLOps จึงต้องมอนิเตอร์สัญญาณเตือนภัยล่วงหน้า (เช่น ยอดทวงถามหนี้) มาประกอบด้วย

## 22.3 Shadow Mode (โหมดเงาทดสอบ)
เมื่อตรวจพบ Drift ทีมจะสร้างโมเดลเวอร์ชันใหม่ (V.2) แต่เราจะไม่เอาไปทับโมเดลเก่าทันที
* **Shadow Deployment:** เอา V.2 ไปวางขนานกับ V.1 บนเซิร์ฟเวอร์โปรดักชัน
* เมื่อลูกค้ากดขอสินเชื่อ ทั้ง V.1 และ V.2 จะทำการรันประมวลผลพร้อมกัน 
* แต่ระบบจะฟังคำตอบจาก V.1 ส่งไปให้ลูกค้า (เพื่อควบคุมความเสี่ยง) และแอบจดคำตอบของ V.2 ไว้หลังบ้าน 
* สิ้นเดือน ทีมงานจะเอาคำตอบมาเทียบกัน ถ้า V.2 ชนะ V.1 จริง ค่อยสับสวิตช์ (Canary/Blue-Green Release) ให้ V.2 ออกโรงเต็มตัว
