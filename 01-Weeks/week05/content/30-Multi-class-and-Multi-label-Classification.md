# 30. การจำแนกประเภทนอกเหนือจาก 0 กับ 1 (Multi-class & Multi-label)

บทเรียนที่ผ่านมา เราโฟกัสไปที่โจทย์แบบ Binary Classification (ใช่/ไม่ใช่, โจร/คนปกติ) แต่ในโลกธุรกิจ เราต้องตอบคำถามที่มีหลายตัวเลือก

## 30.1 Multi-class Classification (การเลือกตอบข้อ ก ข ค ง)
* **สถานการณ์:** ลูกค้าส่งข้อความมาด่าทางอีเมล เราต้องสั่งบอทให้แท็ก (Tag) ว่าอีเมลนี้เป็นเรื่อง `ชำระเงิน`, `สินค้าชำรุด`, หรือ `การจัดส่ง` (บังคับเลือกได้แค่อันเดียว)
* **วิธีแก้แบบ One-vs-Rest (OvR):**
  - คอมพิวเตอร์จะไม่ได้สร้างโมเดล 1 ตัว แต่แอบสร้าง **โมเดล 3 ตัว**
  - โมเดลตัวที่ 1 ถามว่า: "นี่คือเรื่อง ชำระเงิน หรือ ไม่ใช่ชำระเงิน?" (คะแนน 80%)
  - โมเดลตัวที่ 2 ถามว่า: "นี่คือเรื่อง สินค้าชำรุด หรือ ไม่ใช่?" (คะแนน 10%)
  - โมเดลตัวที่ 3 ถามว่า: "นี่คือเรื่อง การจัดส่ง หรือ ไม่ใช่?" (คะแนน 30%)
  - ระบบ DSS จะดูว่าโมเดลไหนตะโกนดังสุด (ได้คะแนนสูงสุด) ก็จะเลือกป้ายนั้น (ในกรณีนี้คือ ชำระเงิน)
* **วิธีแก้แบบ Multinomial (Softmax):** 
  - สร้างสมการเดียว แล้วบีบให้ความน่าจะเป็นของทุกทางเลือกรวมกันได้ 100% พอดี (เช่น 80% + 5% + 15%) เหมาะมากสำหรับ Deep Learning

## 30.2 Multi-label Classification (การเลือกตอบได้หลายข้อ)
* **สถานการณ์:** ใน Netflix หรือ YouTube ภาพยนตร์ 1 เรื่องสามารถเป็นได้ทั้ง `แอคชั่น`, `ตลก`, และ `ไซไฟ` ในเวลาเดียวกัน!
* **ความยาก:** เราไม่สามารถบังคับให้ตอบข้อเดียวได้อีกต่อไป
* **วิธีแก้ปัญหา:**
  1. **Binary Relevance:** สร้างโมเดลแยกอิสระจากกันเลย (โมเดลตลก 1 ตัว, โมเดลแอคชั่น 1 ตัว) แต่ละตัวก็ทาย ใช่/ไม่ใช่ ของตัวเอง (ข้อเสียคือมันไม่รู้ว่าหนังตลกมักจะไม่ค่อยเกี่ยวกับหนังสยองขวัญ)
  2. **Classifier Chains (ต่อคิวทำนาย):** โมเดลตัวที่ 1 ทำนายว่าเป็น "แอคชั่น" ไหม? พอได้คำตอบ ก็ส่งคำตอบนี้ไปเป็น ฟีเจอร์ (ข้อมูลตั้งต้น) ให้โมเดลตัวที่ 2 (ตลก) ทำนายต่อ 
  3. **Deep Learning แบบ Multi-head:** ปลายทางของโครงข่ายประสาทเทียม จะพ่น Sigmoid ออกมา 3 หัวอิสระจากกัน (มีโอกาสได้ 90% ทุกหัวก็ทำได้)

การออกแบบโครงสร้างตารางและ Database เพื่อรองรับ Multi-label ใน Data Warehouse ถือเป็นความท้าทายของวิศวกรข้อมูล เพราะไม่สามารถเก็บแบบ Column เดียวได้ (ต้องใช้ Array หรือ Bridge Table ในการเก็บผลลัพธ์)
