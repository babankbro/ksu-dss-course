# 10. เมทริกซ์ความสับสน (Confusion Matrix) และตัวชี้วัดประสิทธิภาพ

เมื่อเราไม่สามารถเชื่อถือค่า Accuracy ได้ (จากบทที่ 7) วิศวกรจะใช้เครื่องมือที่เรียกว่า **Confusion Matrix (ตารางไขว้ความสับสน)** เพื่อดูว่าโมเดล "พลาดตรงไหนบ้าง"

## 10.1 กายวิภาคของ Confusion Matrix
ตาราง 2x2 ที่แบ่งผลลัพธ์เป็น 4 ช่อง:

| | โมเดลทำนายว่า "ใช่ (Positive)" | โมเดลทำนายว่า "ไม่ใช่ (Negative)" |
|---|---|---|
| **ความจริงคือ "ใช่"** | **True Positive (TP)** <br> ทายว่าทุจริต และทุจริตจริง | **False Negative (FN)** <br> ทายว่าปกติ แต่จริงๆ ทุจริต (โจรหลุดรอด) |
| **ความจริงคือ "ไม่ใช่"** | **False Positive (FP)** <br> ทายว่าทุจริต แต่จริงๆ เป็นคนปกติ (กล่าวหาคนบริสุทธิ์) | **True Negative (TN)** <br> ทายว่าปกติ และปกติจริง |

*หมายเหตุ: ในโลก Data Science สิ่งที่เราสนใจตามหา (เช่น โจร, คนเป็นมะเร็ง, คนจะลาออก) จะถูกสมมติให้เป็นค่า Positive เสมอ*

## 10.2 แกะกล่องสมการชี้วัดความเก่ง (Metrics)

**1. Precision (ความแม่นยำของการแจ้งเตือน)**
* $Precision = \frac{TP}{TP + FP}$
* **ความหมาย:** ในจำนวนเคสทั้งหมดที่โมเดล "ร้องเตือนร้องแหกปาก" ว่าเจอโจร... มันเป็นโจรจริงๆ กี่เปอร์เซ็นต์? (และเป็นเด็กเลี้ยงแกะแหกปากมั่วๆ ไปกี่เปอร์เซ็นต์?)
* **เมื่อใดควรเน้นค่านี้:** เมื่อต้นทุนของการเกิด **False Positive (FP) มีราคาแพงมาก** เช่น โมเดลแนะนำหุ้น ถ้าโมเดลเตือนว่าซื้อเลย (ทั้งที่หุ้นนั้นกาก) ลูกค้าจะเจ๊งยับเยิน เราต้องเน้น Precision สูงๆ ชัวร์ค่อยบอก ไม่ชัวร์ให้เงียบไว้

**2. Recall / Sensitivity (ความสามารถในการกวาดล้าง)**
* $Recall = \frac{TP}{TP + FN}$
* **ความหมาย:** ในบรรดาโจรที่ "มีอยู่จริงทั้งหมดบนโลก" โมเดลสามารถกวาดจับมาได้กี่เปอร์เซ็นต์? (และปล่อยหลุดมือลอดตาข่ายไปกี่เปอร์เซ็นต์?)
* **เมื่อใดควรเน้นค่านี้:** เมื่อต้นทุนของการเกิด **False Negative (FN) มีราคาแพงมาก** เช่น โมเดลคัดกรองมะเร็ง ถ้าโมเดลบอกว่าปกติ (ทั้งที่ผู้ป่วยเป็นมะเร็งระยะแรก) ผู้ป่วยอาจเสียชีวิตได้ เราต้องเน้น Recall สูงๆ คือกวาดคนสงสัยมากักตัวตรวจซ้ำให้หมด ยอมเหนื่อยดีกว่าปล่อยคนตาย

**3. F1-Score (การประนีประนอม)**
* $F1 = 2 \times \frac{Precision \times Recall}{Precision + Recall}$
* **ความหมาย:** เป็นค่าเฉลี่ยแบบ Harmonic Mean ระหว่าง Precision และ Recall (ถ้าตัวใดตัวหนึ่งแย่ ค่า F1 จะตกฮวบทันที) 
* เหมาะสำหรับใช้สรุปเป็นคะแนนตัวเดียวเพื่อแข่งขันกัน ว่าโมเดลไหนสมดุลที่สุด

**สรุปข้อคิดทางธุรกิจ:** โมเดล Data Mining ที่ดี ไม่ใช่โมเดลที่ F1 สูงสุด แต่เป็นโมเดลที่เลือกว่าจะ "ดัน Precision" หรือ "ดัน Recall" ให้สอดคล้องกับงบประมาณและนโยบายความเสี่ยงของบริษัท (Business Alignment)
