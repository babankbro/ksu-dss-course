# 5. การเตรียมข้อมูลและวิศวกรรมฟีเจอร์ (Data Preparation)

กระบวนการนี้เปรียบเสมือนการคัดแยก ปอกเปลือก และหั่นผักก่อนโยนลงกระทะ โมเดล Data Mining จะไม่สามารถย่อยข้อมูลดิบๆ (เช่น ข้อความภาษาไทยยาวๆ หรือช่องว่าง NULL) ได้โดยตรง เราต้องแปลงทุกอย่างให้เป็นตัวเลขที่คอมพิวเตอร์เข้าใจได้

## 5.1 การทำความสะอาดข้อมูล (Cleaning)
* **การจัดการค่าว่าง (Missing Values):** 
  - ลบทิ้ง (Drop) ถ้ามีค่าน้อยมาก
  - เติมค่ากลาง (Imputation) เช่น ใส่ค่าเฉลี่ย (Mean) หรือค่าฐานนิยม (Mode)
  - **ทริควิศวกร:** บางครั้งการเป็นค่าว่างก็มีความหมายในตัวมันเอง! เราควรสร้างคอลัมน์ใหม่ (Missing Indicator) ระบุว่า `is_salary_missing = 1` เพราะบางทีคนที่ชอบปกปิดเงินเดือน มักจะเป็นคนที่มีแนวโน้มเบี้ยวหนี้
* **การจัดการ Outlier (ค่าผิดปกติ):**
  - เงินเดือน 1,000,000 บาท เป็นข้อมูลกรอกผิด หรือเขาเป็นเศรษฐีจริงๆ? ต้องสืบสวนก่อนจะ Cap (กดให้ยอดไม่เกินขีดจำกัด) หรือ Remove ทิ้ง

## 5.2 การแปลงรูปและการเข้ารหัส (Transformation & Encoding)
โมเดลทางคณิตศาสตร์อ่านข้อความไม่ออก เราต้องเข้ารหัสข้อความให้เป็นตัวเลข:
* **One-hot Encoding (สร้างคอลัมน์ดัมมี่):**
  - เหมาะกับข้อมูลประเภทระบุกลุ่ม (Nominal) ที่ไม่มีลำดับสูงต่ำ เช่น `สีรถ (แดง, ดำ, ขาว)`
  - จะถูกแตกออกเป็น 3 คอลัมน์: `is_red`, `is_black`, `is_white` มีค่าเป็น 0 หรือ 1
* **Ordinal Encoding (เข้ารหัสแบบเรียงลำดับ):**
  - เหมาะกับข้อมูลที่มีความหมายสูงต่ำ (Ordinal) เช่น `ระดับการศึกษา (ประถม, มัธยม, ปริญญา)`
  - จะถูกเปลี่ยนเป็นเลข `1, 2, 3`
* **Standardization/Normalization (การปรับสเกล):**
  - คอลัมน์ "อายุ" วิ่งตั้งแต่ 18-80 แต่คอลัมน์ "เงินเดือน" วิ่งตั้งแต่ 15,000-200,000
  - ถ้าใช้อัลกอริทึมจำพวก Neural Network หรือ KNN มันจะให้ความสำคัญกับเงินเดือนมากกว่าอายุเพราะเลขเยอะกว่า เราจึงต้องจับทุกคอลัมน์มาย่อส่วน (Scale) ให้มีค่าอยู่ระหว่าง 0 ถึง 1 หรือมีค่าเฉลี่ยเป็น 0 เสมอ
  - *(หมายเหตุ: อัลกอริทึมตระกูล Decision Tree ไม่แคร์เรื่องความต่างของ Scale)*

## 5.3 วิศวกรรมฟีเจอร์ (Feature Engineering)
นี่คือศิลปะขั้นสูงสุดของ Data Scientist มันคือการนำข้อมูลที่มีอยู่ มาประกอบร่างเป็นตัวแปรใหม่ที่มีความหมายทางธุรกิจลึกซึ้งขึ้น
* **ตัวอย่าง:** เรามีตารางบิลบัตรเครดิตดิบๆ (Raw)
* **Feature ใหม่ 1:** `Total_spending_last_7_days` (ยอดรูดบัตรสะสม 7 วันย้อนหลัง)
* **Feature ใหม่ 2:** `Ratio_weekend_spending` (สัดส่วนการใช้จ่ายวันหยุด / วันธรรมดา)
* **Feature ใหม่ 3:** `Days_since_last_payment` (จำนวนวันที่ห่างจากการจ่ายเงินครั้งล่าสุด)

**กฎเหล็กของ Feature Engineering:** ข้อมูลที่นำมาสร้างตัวแปรเหล่านี้ **ต้องเป็นข้อมูลที่มีอยู่จริง ณ เวลาที่โมเดลต้องทำนาย (Availability Time)** ห้ามเผลอหยิบข้อมูลอนาคตมาผูกรวมเด็ดขาด!
