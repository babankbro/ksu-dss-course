# 18. ความมั่นคงปลอดภัยและการควบคุมสิทธิ์ในสถาปัตยกรรม DSS (Security & Access Control)

DSS เป็นที่รวมของข้อมูลที่ละเอียดอ่อนที่สุดของบริษัท ไม่ว่าจะเป็นตัวเลขผลกำไรสุทธิ ข้อมูลเงินเดือนพนักงาน หรือโมเดลกลยุทธ์ลับ หากสถาปัตยกรรมขาดการวางระบบความปลอดภัยตั้งแต่ต้น (Security by Design) ระบบจะกลายเป็นระเบิดเวลาที่รอวันสร้างความเสียหาย 

## 18.1 สถาปัตยกรรม Zero Trust (ความไว้วางใจเป็นศูนย์)
* ในอดีต องค์กรเชื่อว่าหากพนักงานล็อกอินเข้า Wi-Fi ในตึกบริษัทได้แล้ว แปลว่าปลอดภัย (Perimeter security) 
* สถาปัตยกรรม **Zero Trust** ใน DSS สมัยใหม่ จะไม่เชื่อใจใครทั้งสิ้น ไม่ว่าคุณจะอยู่ในบริษัทหรือทำงานที่บ้าน 
* **กลไก:** ทุกครั้งที่หน้าจอ UI ส่งคำสั่งดึงผลลัพธ์จาก Model Layer ระบบหลังบ้านจะต้องขอตรวจสอบโทเคนยืนยันตัวตน (Authentication Token) เสมอ ทำให้แม้แฮกเกอร์จะเจาะเข้ามาในเครือข่ายบริษัทได้ ก็ไม่สามารถดึงข้อมูลจากตัวโมเดลได้

## 18.2 Row-Level Security (RLS) และ Column-Level Security
การให้สิทธิ์ผู้ใช้แบบง่ายๆ เช่น "เข้าดูระบบได้/ดูไม่ได้" นั้นไม่เพียงพอสำหรับ DSS องค์กรใหญ่ต้องใช้ RLS เพื่อบีบหน้าจอให้แสดงผลต่างกันไปตามระดับพนักงาน:
* **Row-Level Security (การกรองข้อมูลระดับแถว):** 
  - ระบบใช้ Dashboard หน้าตาเดียวกันเป๊ะ แต่เมื่อ "ผู้จัดการสาขาเชียงใหม่" ล็อกอิน เขาจะเห็นแท่งกราฟยอดขายเฉพาะสาขาตัวเองเท่านั้น (เห็นแค่แถวข้อมูลเชียงใหม่)
  - เมื่อ "ผู้อำนวยการฝ่ายภูมิภาค" ล็อกอิน เขาจะเห็นข้อมูลยอดขายรวมของทุกจังหวัดในภาคเหนือ
* **Column-Level Security (การปกปิดระดับคอลัมน์):**
  - อนุญาตให้พนักงานการตลาดดูตารางข้อมูลลูกค้าเพื่อวิเคราะห์พฤติกรรมได้ แต่คอลัมน์ "หมายเลขบัตรเครดิต" และ "เบอร์โทรศัพท์" จะถูกปิดตา (Masking) เป็นเครื่องหมายกากบาท (xxx-xxx-xx) 

## 18.3 การเข้ารหัสข้อมูล (Encryption)
* **Data at Rest (ตอนข้อมูลหลับ):** ฐานข้อมูลและโมเดลทั้งหมดที่เก็บในฮาร์ดดิสก์จะต้องถูกเข้ารหัส แม้ขโมยจะยกเซิร์ฟเวอร์ออกไปได้ ก็เปิดอ่านข้อมูลไม่ได้
* **Data in Transit (ตอนข้อมูลวิ่ง):** ระหว่างที่ UI ส่งข้อมูลไปให้ Model ประมวลผล ข้อมูลนั้นต้องวิ่งผ่านอุโมงค์นิรภัย (HTTPS/TLS) เพื่อป้องกันการดักจับข้อมูลระหว่างทาง

## 18.4 ระบบป้องกันข้อมูลรั่วไหล (DLP: Data Loss Prevention)
ใน Document-driven DSS ผู้บริหารอาจต้องการโหลดรายงานสรุปออกมาเป็นไฟล์ PDF หรือ Excel ระบบต้องมีสถาปัตยกรรมป้องกันข้อมูลรั่วไหล เช่น:
- การฝังลายน้ำดิจิทัล (Digital Watermark) จางๆ ระบุชื่อผู้ที่ดาวน์โหลดไฟล์นั้นบนทุกหน้ากระดาษ
- การจำกัดสิทธิ์ (Disable Export) ไม่อนุญาตให้กดส่งออกเป็น Excel หากข้อมูลมีจำนวนเกิน 100 แถว ป้องกันพนักงานขโมยฐานลูกค้าออกไป

สถาปนิก DSS ต้องสร้างสมดุล (Trade-off) ระหว่าง "ความปลอดภัยที่รัดกุมที่สุด" กับ "ความง่ายในการใช้งานของผู้บริหาร" หากระบบใส่รหัสผ่านหลายชั้นจนเข้ายากเกินไป ผู้บริหารจะเลิกใช้แล้วหวนกลับไปใช้วิธีโทรศัพท์ถามลูกน้องเหมือนเดิม
