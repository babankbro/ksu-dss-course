# 17. เครื่องมือและเทคโนโลยีส่วนต่อประสานผู้ใช้สมัยใหม่ (UI & Visual Analytics)

ระบบย่อย **User Interface (UI)** ไม่ใช่แค่เรื่องของความสวยงาม แต่เป็นศาสตร์ของการออกแบบสถาปัตยกรรมสารสนเทศเพื่อให้มนุษย์รับรู้และตัดสินใจได้ไวที่สุด ในองค์กรขนาดใหญ่ ทางเลือกในการออกแบบ UI มีความหลากหลาย ขึ้นอยู่กับระดับชั้นความลึกของการตัดสินใจ

## 17.1 BI & Dashboard Tools (เครื่องมือสำเร็จรูป)
สำหรับ DSS สาย Data-Driven ที่ไม่ได้มีความต้องการแปลกประหลาดมากนัก องค์กรมักเลือกใช้ (Buy) ซอฟต์แวร์สำเร็จรูป เพราะคุ้มค่า ประหยัดเวลา และพนักงานคุ้นเคย:
* **Tableau:** จุดเด่นคือการวาดกราฟที่ซับซ้อนและการทำ Visual Analytics ระดับลึก เหมาะกับนักวิเคราะห์ข้อมูล (Data Analyst)
* **Microsoft Power BI:** นิยมสูงสุดในองค์กร เพราะเชื่อมต่อกับระบบ Microsoft เดิมที่มีอยู่แล้ว (Excel, SQL Server) ทำงานบนคลาวด์ได้ทันที
* **Qlik Sense:** โดดเด่นด้าน Associative Engine ที่ยอมให้ผู้ใช้สุ่มคลิกค้นหาข้อมูลข้ามไปมาได้อย่างอิสระ ไม่ต้องเดินตามเส้นทางที่โปรแกรมเมอร์กำหนดไว้ล่วงหน้า

## 17.2 Custom Web UI Frameworks (เครื่องมือพัฒนาเอง)
ในหลายกรณี ระบบ BI สำเร็จรูป ไม่สามารถตอบโจทย์ "กระบวนการตัดสินใจ (Action Loop)" ได้ เช่น เมื่อดูกราฟเสร็จแล้ว ต้องการกดปุ่ม "อนุมัติสั่งซื้อ" ในหน้าจอเดียวกัน ระบบ BI มักจะทำไม่ได้ สถาปนิกจึงต้องสร้าง Web UI ขึ้นมาเอง (Build):
* **React, Vue.js, Angular:** เฟรมเวิร์กภาษา JavaScript สำหรับสร้างหน้าจอแอปพลิเคชันที่โต้ตอบรวดเร็วและฝังแบบฟอร์มการตัดสินใจเข้าไปได้
* **D3.js และ ECharts:** ไลบรารีสำหรับวาดกราฟที่ปรับแต่งได้ 100% สามารถวาดภาพกราฟความรู้ (Knowledge Graph) แบบมีปฏิสัมพันธ์ ย่อ ขยาย และแสดงอนิเมชันที่ซับซ้อนกว่าที่โปรแกรมสำเร็จรูปจะทำได้
* **Streamlit และ Dash:** เป็นเครื่องมือที่มาแรงมากในยุคนี้ เพราะอนุญาตให้ฝั่ง Data Scientist ที่เขียนแต่ภาษา Python สามารถสร้างหน้าเว็บกราฟิกแบบโต้ตอบ (What-if Analysis UI) เพื่อให้ผู้บริหารใช้งานได้ภายในไม่กี่บรรทัด โดยไม่ต้องเรียนรู้การเขียนหน้าเว็บแบบปกติ

## 17.3 สถาปัตยกรรมแบบ Embedded Analytics
ทางเลือกที่นิยมสูงสุดในปัจจุบันคือการ "พบกันครึ่งทาง" 
* แทนที่จะให้ผู้จัดการสาขาเปิดแอปขายหน้าร้าน (POS) ไว้หน้าจอซ้าย และเปิด Power BI ไว้หน้าจอขวา 
* สถาปนิกจะฝัง (Embed) กราฟวิเคราะห์คำแนะนำจากโมเดล ลงไปในแอป POS เดิมเลย (เช่น มีแถบสีเขียวแดงบอกความเสี่ยงปรากฏอยู่ข้างๆ ชื่อลูกค้าทันทีที่ค้นหา) 
* วิธีนี้เรียกว่า **In-context Decision Support** ซึ่งช่วยลดแรงเสียดทาน (Friction) ในการทำงาน ผู้ใช้ไม่ต้องเปลี่ยนหน้าต่างแอปพลิเคชันไปมา ทำให้เปอร์เซ็นต์การใช้งาน DSS พุ่งสูงขึ้นอย่างก้าวกระโดด
