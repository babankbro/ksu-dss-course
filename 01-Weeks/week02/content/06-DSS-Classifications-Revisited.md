# 6. การจำแนกประเภท DSS ตามแกนทรัพยากรหลัก (Architectural Perspective)

สัปดาห์ที่แล้วเราได้ทำความรู้จักกับประเภทของ DSS ตามกรอบของ D.J. Power ไปบ้างแล้ว ในสัปดาห์นี้เราจะนำระบบทั้ง 5 ประเภทกลับมาพิจารณาอีกครั้ง แต่จะมองในมุมของ **"สถาปัตยกรรมและการจัดสรรทรัพยากร (Resource Allocation)"** ว่าระบบประเภทไหนให้ความสำคัญกับชิ้นส่วนใดเป็นพิเศษ

## 6.1 Data-Driven DSS
* **ทรัพยากรหลัก:** ฐานข้อมูลขนาดมหึมา (Big Data) และท่อส่งข้อมูล (Data Pipelines)
* **จุดเน้นทางสถาปัตยกรรม:** ให้ความสำคัญกับ Data Management Subsystem มากที่สุด ต้องลงทุนหนักไปกับ Data Warehouse, กลไก ETL ที่ทำงานรวดเร็ว และเซิร์ฟเวอร์แบบ Cluster เพื่อรองรับการดึงข้อมูล (Query) ปริมาณมหาศาล
* **ระบบที่ลดทอน:** Model Management อาจจะเป็นแค่สมการทางคณิตศาสตร์ง่ายๆ (บวก ลบ หาค่าเฉลี่ย) ไม่ซับซ้อนมาก
* **ตัวอย่าง:** Dashboard สรุปยอดขายสินค้าของร้านสะดวกซื้อรายวัน

## 6.2 Model-Driven DSS
* **ทรัพยากรหลัก:** อัลกอริทึม, กลไกการแก้ปัญหา (Solver) และสมรรถนะการคำนวณ (Compute Power / CPU)
* **จุดเน้นทางสถาปัตยกรรม:** ให้ความสำคัญกับ Model Management Subsystem ต้องลงทุนกับเซิร์ฟเวอร์ประมวลผลสูง (High Performance Computing) หรือ GPU เพราะบางโมเดลเช่น การหาเส้นทางขนส่ง อาจต้องคำนวณความน่าจะเป็นนับล้านๆ รูปแบบ (Combinatorial problems)
* **ระบบที่ลดทอน:** ข้อมูลนำเข้ามักมีปริมาณไม่มากนัก (Small dataset) ผู้ใช้อาจแค่ป้อนตัวแปรไม่กี่ตัวผ่านหน้าจอ
* **ตัวอย่าง:** ระบบคำนวณและวางแผนการเดินเครื่องจักรในโรงงาน

## 6.3 Knowledge-Driven DSS
* **ทรัพยากรหลัก:** ฐานกฎเกณฑ์ (Rule Base) และเอนจิ้นอนุมานผล (Inference Engine)
* **จุดเน้นทางสถาปัตยกรรม:** ให้ความสำคัญกับ Knowledge-based Subsystem ต้องออกแบบโครงสร้างข้อมูลเชิงกราฟ (Knowledge Graph) หรือโครงสร้างตรรกะที่สามารถสืบค้นและจับคู่รูปแบบเหตุผลได้อย่างแม่นยำ
* **ความท้าทาย:** การอัปเดตกฎเกณฑ์เมื่อโลกเปลี่ยนไป ต้องมีหน้าจอให้ผู้เชี่ยวชาญ (เช่น นักกฎหมาย แพทย์) เข้ามาเพิ่มหรือแก้กฎได้เอง โดยไม่ต้องพึ่งโปรแกรมเมอร์ (No-code rule builder)
* **ตัวอย่าง:** ระบบคัดกรองอาการผู้ป่วยเบื้องต้นบนแอปพลิเคชัน

## 6.4 Communication-Driven DSS (Group DSS)
* **ทรัพยากรหลัก:** โครงข่ายการสื่อสาร (Network) และกลไกการประสานงาน (Concurrency Control)
* **จุดเน้นทางสถาปัตยกรรม:** ให้ความสำคัญกับ User Interface และระบบหลังบ้านที่รองรับผู้ใช้หลายคน (Multi-user System) ต้องจัดการเรื่อง Data Synchronization ให้ดี เช่น ถ้านาย ก. แก้ไขกระดานโหวต หน้าจอของนาย ข. ต้องอัปเดตแบบ Real-time (WebSockets)
* **ระบบที่ลดทอน:** อาจจะไม่มี Model ทางคณิตศาสตร์ใดๆ เลย เพราะพึ่งพาสมองของ "กลุ่มผู้ใช้" ในการหาคำตอบแทน
* **ตัวอย่าง:** ระบบห้องบัญชาการภัยพิบัติ (War room) หรือระบบระดมสมองแบบนิรนาม

## 6.5 Document-Driven DSS
* **ทรัพยากรหลัก:** ไฟล์เอกสารที่ไม่มีโครงสร้าง (PDF, Word, Text, Image) 
* **จุดเน้นทางสถาปัตยกรรม:** ต้องมีเอนจิ้นการค้นหาขั้นสูง (Search Engine), การทำดัชนี (Indexing), และเทคโนโลยีประมวลผลภาษาธรรมชาติ (NLP) หรือ Vector Database
* **ความท้าทาย:** การแปลงข้อมูลที่ไม่มีโครงสร้างให้อยู่ในรูปที่จับต้องและค้นหาได้ รวดเร็ว และกินพื้นที่เก็บน้อย
* **ตัวอย่าง:** ระบบค้นหาและเทียบเคียงสัญญาทางกฎหมายนับแสนฉบับ

## ระบบผสม (Hybrid Architecture)
ในสถาปัตยกรรมระดับองค์กร (Enterprise Architecture) ระบบจริงมักเป็น **Hybrid DSS** กล่าวคือ นำสถาปัตยกรรมเด่นของแต่ละสายมารวมกัน
*ตัวอย่าง:* ระบบวินิจฉัยโรค (Clinical DSS) ต้องดึงประวัติคนไข้ 10 ปี (Data-driven) มาเข้าโมเดลพยากรณ์ความเสี่ยงโรคหัวใจ (Model-driven) จากนั้นเทียบกับระเบียบกระทรวงสาธารณสุข (Knowledge-driven) อ้างอิงเอกสารงานวิจัยล่าสุด (Document-driven) และส่งให้คลินิกเฉพาะทางโหวตยืนยัน (Communication-driven)

การเข้าใจแกนทรัพยากรของแต่ละประเภท ช่วยให้สถาปนิกไอทีสามารถจัดงบประมาณ ซื้อฮาร์ดแวร์ หรือเลือกผู้ให้บริการคลาวด์ได้ตรงตามคอขวด (Bottleneck) ที่แท้จริงของระบบ
