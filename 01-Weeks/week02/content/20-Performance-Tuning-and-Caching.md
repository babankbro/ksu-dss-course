# 20. การเพิ่มประสิทธิภาพระบบและการทำแคช (Performance Tuning & Caching)

สถาปัตยกรรมของ DSS อาจจะออกแบบมาสมบูรณ์แบบในกระดาษ แต่พอเอาไปใช้งานจริง ข้อมูลมีขนาดหลายเทระไบต์ (Terabytes) หน้าจอ Dashboard อาจจะหมุนโหลดนานถึง 2 นาที ซึ่งผู้บริหารย่อมไม่รอ การรีดประสิทธิภาพความเร็ว (Performance Tuning) จึงเป็นงานหนักของสถาปนิก

## 20.1 การทำดัชนี (Database Indexing)
ในชั้น Data Management การดึงข้อมูลแบบสุ่ม (Scan) จาก 100 ล้านบรรทัดเพื่อหายอดขายของ "สมชาย" จะช้ามาก 
* สถาปนิกต้องสร้าง **Index (ดัชนี)** ให้กับคอลัมน์ที่ถูกค้นหาบ่อยๆ เหมือนสารบัญหนังสือ ทำให้ฐานข้อมูลกระโดดไปดึงบรรทัดนั้นได้ภายใน 0.1 วินาที
* อย่างไรก็ตาม การทำ Index มากเกินไป จะทำให้ตอนนำเข้าข้อมูล (Data Ingestion) ช้าลง จึงต้อง Trade-off ให้เหมาะสม

## 20.2 พลังของการทำ Caching (หน่วยความจำแคช)
หลักการของ Cache คือ **"ถ้ามีคนเคยถามคำถามนี้แล้ว อย่าเสียเวลาคำนวณใหม่ ให้เอาคำตอบที่จดไว้ไปตอบเลย"**
* **In-memory Database (เช่น Redis, Memcached):** หากตอนเช้า ผู้จัดการฝ่ายขายภาคเหนือคลิกดู "รายงานยอดขายเดือนนี้" ระบบจะใช้เวลา 10 วินาทีคำนวณเสร็จ แต่ระบบจะแอบเอาผลลัพธ์ไปเก็บไว้ใน Redis (แรมความเร็วแสง) 
* พอตอนบ่าย ผู้ช่วยผู้จัดการกดดูรายงานหน้าเดียวกันเป๊ะ ระบบจะไม่กลับไปคำนวณใหม่ แต่จะดึงภาพจาก Redis ไปแสดงให้ดูเลยภายใน 0.01 วินาที 
* สถาปัตยกรรมนี้จำเป็นอย่างยิ่งสำหรับ Dashboard ระดับองค์กรที่มีพนักงานเปิดดูพร้อมกัน 1,000 คน

## 20.3 วัฏจักรพรีคอมพิวต์ (Pre-Computation & Materialized Views)
แทนที่จะปล่อยให้ผู้บริหารกดหน้าจอแล้วระบบค่อยทำงานหนัก สถาปนิก DSS สายวิศวกรรมข้อมูลจะใช้วิธี "คำนวณรอไว้ตอนดึก"
* **Materialized Views:** เป็นการสร้างตารางข้อมูลสรุปตั้งไว้ล่วงหน้า (เช่น รันยอดสรุปแยกตามสาขาและรายเดือนเสร็จสรรพตั้งแต่ตอนตี 2)
* เมื่อผู้บริหารมาดูตอนเช้า เขาแค่คลิกดูตารางที่คำนวณไว้เสร็จแล้ว 
* วิธีนี้ทำให้อินเทอร์เฟซตอบสนองเร็วแบบก้าวกระโดด แต่มีข้อเสียคือ ผู้บริหารไม่สามารถเจาะลึก (Drill-down) ถึงระดับบิลรายใบได้ ถ้าไม่ได้ออกแบบไว้ล่วงหน้า

## 20.4 Query Optimization
บางครั้งความช้าไม่ได้อยู่ที่เซิร์ฟเวอร์ แต่อยู่ที่การเขียนคำสั่ง (Query) 
* สถาปนิกต้องเข้ามาปรับเปลี่ยนคำสั่ง SQL หรือจัดโครงสร้างตารางใหม่ (เช่น ลดการ JOIN ตารางที่ยุ่งเหยิง) ทำ Denormalization คือยอมให้มีข้อมูลซ้ำซ้อนบ้าง เพื่อแลกกับความเร็วในการอ่านข้อมูล
