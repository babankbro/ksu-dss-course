# 15. MLOps และการให้บริการแบบจำลอง (MLOps & Model Serving in DSS)

ในระบบย่อย **Model Management Subsystem** ปัญหาที่พบบ่อยที่สุดไม่ใช่เรื่อง "ไม่มีใครสร้างโมเดลเก่งๆ ได้" แต่คือ "สร้างเสร็จแล้วเอาไปใช้จริงไม่ได้" (Models stuck in Jupyter Notebooks) การนำโมเดลไปฝังไว้ในแอปพลิเคชัน DSS ให้ทำงานแบบเสถียร ต้องการกระบวนการทางวิศวกรรมที่เรียกว่า **MLOps (Machine Learning Operations)**

## 15.1 MLOps คืออะไร?
MLOps คือการนำหลักการของวิศวกรรมซอฟต์แวร์ (DevOps) มาใช้กับการพัฒนาตัวแบบจำลอง (Model) เป้าหมายคือการทำให้วงจรชีวิตของโมเดล (สร้าง ➔ ทดสอบ ➔ ติดตั้ง ➔ เฝ้าระวัง ➔ สร้างใหม่) เป็นไปอย่างอัตโนมัติ รวดเร็ว และตรวจสอบได้

## 15.2 การนำโมเดลไปใช้งาน (Model Serving)
เมื่อสร้างโมเดลพยากรณ์อุปสงค์ (Demand Forecasting) เสร็จ สถาปนิกจะทำอย่างไรให้หน้าจอ (UI) ดึงผลลัพธ์จากโมเดลไปโชว์ได้? 
มี 2 สถาปัตยกรรมหลักในการทำ Model Serving:

1. **Batch Prediction (พยากรณ์ล่วงหน้าและเก็บไว้):**
   - โมเดลจะทำงานตอนตี 3 พยากรณ์อุปสงค์ของสินค้าทุกชิ้นในร้าน แล้วบันทึกคำตอบลงฐานข้อมูล (Database)
   - พอผู้บริหารตื่นเช้ามากดปุ่มที่หน้าจอ UI ระบบจะไปอ่านจากฐานข้อมูลทันที
   - **ข้อดี:** หน้าจอทำงานเร็วมาก เพราะไม่ต้องรอรันสมการ

2. **Real-time Prediction (Online Inference):**
   - การนำโมเดลไปบรรจุไว้ในกล่อง (Container) และเปิด API ให้บริการ
   - เมื่อลูกค้ากดปุ่มขอสินเชื่อผ่านแอป ข้อมูลจะวิ่งมาที่ Model API โมเดลจะคำนวณสดๆ ในวินาทีนั้น แล้วคืนค่า (Return) คำตอบกลับไปทันที
   - **ข้อดี:** ทันต่อบริบทล่าสุด เหมาะกับการจับทุจริต หรือระบบตั้งราคาแบบ Dynamic Pricing

## 15.3 การทดสอบโมเดลในโลกจริง (A/B Testing & Shadow Mode)
ก่อนที่จะปล่อยโมเดลเวอร์ชันใหม่ (Version B) ไปใช้ตัดสินใจแทนมนุษย์ สถาปนิก DSS ต้องมีกระบวนการลดความเสี่ยง:
* **Shadow Mode (โหมดเงา):** ปล่อยโมเดลใหม่รันคู่ขนานไปกับโมเดลเก่า โดยที่ผู้ใช้ระบบ (End-user) ไม่เห็นผลลัพธ์ของโมเดลใหม่ เพื่อเก็บข้อมูลเปรียบเทียบว่าโมเดลใหม่ทำผลงานได้ดีกว่าจริงหรือไม่
* **A/B Testing (Canary Release):** ส่งผลลัพธ์จากโมเดลใหม่ให้กับผู้ใช้แค่ 10% (เช่น ลูกค้าภาคเหนือ) และโมเดลเก่า 90% หากโมเดลใหม่ให้ผลกำไรที่ดีกว่า จึงค่อยทยอยขยายสัดส่วนการใช้งานจนครบ 100%

การวางสถาปัตยกรรมแบบ MLOps ทำให้องค์กรกล้าที่จะ "เปลี่ยนโมเดล" ให้ทันต่อเหตุการณ์ของโลกได้ตลอดเวลา โดยไม่รู้สึกกังวลว่าระบบจะล่ม
