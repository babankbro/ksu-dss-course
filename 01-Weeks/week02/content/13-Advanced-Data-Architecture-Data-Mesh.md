# 13. สถาปัตยกรรมข้อมูลขั้นสูง (Advanced Data Architecture)

การพัฒนาระบบ DSS ขนาดใหญ่ในองค์กรระดับชาติ (Enterprise-scale DSS) แค่มี Data Warehouse เพียงแห่งเดียวอาจไม่ตอบโจทย์ความคล่องตัวอีกต่อไป โลกของสถาปัตยกรรมข้อมูลได้ก้าวไปสู่รูปแบบที่กระจายศูนย์และฉลาดขึ้น

## 13.1 Data Mesh (ตาข่ายข้อมูล)
* **ปัญหาเดิม:** การรวบรวมข้อมูลทุกอย่างมาไว้ที่ Data Warehouse ส่วนกลาง ทำให้ทีม Data Engineer ส่วนกลางทำงานหนักจนกลายเป็นคอขวด (Bottleneck) การจะสร้าง DSS ตัวใหม่ต้องรอคิวเป็นเดือน
* **แนวคิด Data Mesh:** เปลี่ยนมุมมองต่อข้อมูลให้เป็น **"ผลิตภัณฑ์ (Data as a Product)"** กระจายความเป็นเจ้าของ (Ownership) กลับไปให้แผนกที่เป็นคนสร้างข้อมูล เช่น แผนกการตลาดดูแลข้อมูลลูกค้า แผนกผลิตดูแลข้อมูลเครื่องจักร
* **การทำงาน:** แต่ละแผนกจะมีระบบข้อมูลของตนเอง แต่มีมาตรฐานร่วมกัน (Federated Governance) เมื่อ DSS ของแผนกการเงินต้องการข้อมูลลูกค้า ก็สามารถเชื่อมต่อผ่าน API ของแผนกการตลาดได้โดยตรง สถาปัตยกรรมนี้ทำให้การสร้าง DSS ย่อยๆ ทั่วองค์กรทำได้เร็วขึ้นมาก

## 13.2 Data Fabric (ผืนผ้าใบข้อมูล)
* **ปัญหาเดิม:** ข้อมูลขององค์กรถูกจัดเก็บกระจัดกระจาย ทั้งในระบบ Cloud (AWS, Azure) และระบบ On-premise (เซิร์ฟเวอร์ในบริษัท) ผู้บริหารหาข้อมูลไม่เจอ
* **แนวคิด Data Fabric:** เป็นสถาปัตยกรรมที่ใช้ AI และ Machine Learning เข้ามาถักทอข้อมูลจากทุกแหล่งให้ดูเหมือนเป็นผืนเดียวกัน โดยที่ไม่ได้ย้ายข้อมูลจริงๆ
* **การทำงาน:** Data Fabric จะทำหน้าที่เป็นแคตตาล็อกอัจฉริยะ (Active Metadata) คอยแนะนำสถาปนิก DSS ว่า "ถ้าคุณกำลังจะทำโมเดลพยากรณ์ยอดขาย คุณควรดึงข้อมูล 3 ตารางนี้จากเซิร์ฟเวอร์ที่สิงคโปร์มาประกอบกัน" ช่วยลดเวลาค้นหาข้อมูลได้อย่างมหาศาล

## 13.3 Lambda Architecture และ Kappa Architecture
สำหรับ DSS ที่ต้องรองรับทั้งข้อมูลสรุปรายเดือน (Batch) และข้อมูลกระแสน้ำแบบเรียลไทม์ (Streaming)
* **Lambda Architecture:** แบ่งท่อส่งข้อมูลเป็น 2 สาย คือ **Batch Layer** (ประมวลผลข้อมูลก้อนใหญ่ย้อนหลัง ได้ความแม่นยำสูง) และ **Speed Layer** (ประมวลผลข้อมูลวินาทีปัจจุบัน ได้ความเร็วแต่ความแม่นยำต่ำกว่า) แล้วนำมาแสดงผลรวมกันที่หน้าจอ
* **Kappa Architecture:** มองทุกอย่างเป็นสตรีมมิ่ง (Streaming) คือไม่มีสาย Batch ข้อมูลทุกหยดไหลผ่านท่อประมวลผลแบบ Real-time (เช่น Apache Kafka) ทำให้การดูแลระบบง่ายขึ้น เพราะมีโค้ดประมวลผลแค่ชุดเดียว
